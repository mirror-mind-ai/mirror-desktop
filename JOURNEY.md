# Mirror Desktop
**Status:** active
**Stage:** Transfer accepted from Nautilus Harness

## Description

Mirror Desktop is the first-party desktop application for the Mirror Mind ecosystem. It continues the Tauri application body incubated as Nautilus Harness, preserving the proven Journey-bound Pi and Mirror operating loop while repositioning the product under the canonical `mirror-mind-ai/mirror-desktop` repository.

## Lineage

Mirror Desktop inherits from Nautilus Harness as predecessor history, not as a bulk reassignment of past records. Nautilus Harness keeps its historical conversations, releases, refinement records, decisions and validation evidence. Mirror Desktop carries forward the product intent, source code history, exploratory handoff and selected design direction needed for future construction.

The founding transition artifact is:

```text
docs/project/explorations/mirror-desktop-core-installer-and-tauri-app-migration/
```

The originating exploratory story is `Mirror Desktop emerges from the Tauri Harness`.

## Current focus

Establish Mirror Desktop as the canonical continuation of Nautilus Harness, adapt the Tauri Harness transition design to the dedicated `mirror-desktop` repository topology, and prepare the first roadmap slice from the exploratory handoff.

## Near slice

Translate the exploratory handoff into Builder-ready roadmap work without treating it as already-settled implementation scope. Before broad renaming, create a namespace and durable-state inventory that classifies product identity, generic Mirror-owned capabilities, Nautilus method semantics and legacy compatibility coordinates.

Bundle identifiers, app-data roots, persisted files, session and conversation prefixes, generation identities, schemas, receipts and channel isolation remain first-class migration concerns.

## Transfer boundaries

Open tasks from Nautilus Harness are not transferred automatically. Historical records remain attached to Nautilus Harness. Future work should be recreated in Mirror Desktop only when it still serves the new product boundary and carries explicit provenance.
