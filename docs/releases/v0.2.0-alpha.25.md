# v0.2.0-alpha.25 — Always Legible Context Reading

**Date:** 2026-09-28

## Highlights

- Replaces visible context waiting sentences with the compact `<value>/<window>` reading.
- Shows the selected model's window from the live Pi catalog even when token usage is unknown.
- Marks approximate readings with `~` instead of hiding them.
- Keeps a Conversation's token count visible across Model Intent switches.
- Estimates a fresh Conversation before the first assistant reply.
- Uses `estimatedTokensAfter` after compaction so the reading remains useful immediately.
- Adds bounded follow-up reads instead of freezing forever after the first retry window.
- Demotes the stale static context-window table to a last-resort fallback.

## Where We Started

Mirror Desktop often showed `Checking context stats…`, `Waiting for first context usage…`, or
`Waiting for usage from selected model…` in the footer. The terminal Pi experience was better:
it kept a context reading on screen even when the percent was only approximate or unknown.

That difference mattered in daily use. The Navigator needed to know whether a Conversation was
near its limit, whether it should be compacted, and whether switching to a smaller model window
would be safe. Desktop was withholding the rough number exactly when rough guidance was better
than silence.

## What Changed

**The footer now has one grammar.** The visible label is always `<value>/<window>`: measured
readings appear as `41%/272K`, approximations as `~41%/272K`, unknown counts as `?/272K`, and
missing sessions as `–/272K`. The longer diagnostic sentences moved to the tooltip instead of
occupying the footer line.

**The model window comes from the live catalog.** Desktop already loaded Pi's model catalog at
startup, including the windows for the active Model Intents. The release makes that catalog the
visible authority for the footer reading and leaves the older static table only as a final
fallback for stream events that cannot access the catalog.

**Readings survive model switches.** A token count belongs to the Conversation, not to the
model that last measured it. When the selected model differs from the measuring model, Desktop
keeps the count and marks the percentage approximate with `~` instead of discarding it.

**Estimates are first-class, not absent.** A new Conversation can show an estimate before the
first assistant reply. A compaction uses the `estimatedTokensAfter` value Pi already reports.
Both remain marked approximate until a later model response reports usage.

**The app keeps looking, within a bound.** The old sub-second retry could give up and leave the
footer frozen until another turn happened to run. The app now schedules a few spaced follow-up
reads while the reading has not settled, then stops rather than polling indefinitely.

## Conscious Exclusions

- No exact cross-tokenizer remeasurement is introduced; approximate readings remain marked.
- No context-budgeting or model-selection policy changes ship in this release.
- No unbounded file watching or polling of Pi sessions is added.
- No new compaction trigger policy is introduced.

## What We Learned

The missing data was mostly not missing. Desktop already knew the selected model's context
window and already had usable Conversation counts; it was discarding them for the sake of an
exactness contract the Navigator did not need in that moment.

The better truth is not silence. A marked approximation says exactly what it is and still gives
the Navigator orientation. That is especially important when switching between 1M-window models
and 272K-window models: the same Conversation can be safe in one place and dangerous in the
other, and hiding the reading removes the only signal that makes the difference visible.

## Validation

The Navigator validated the Eval build. The footer now keeps a reading visible, carries `~`
across approximation cases, survives model switches without blanking, and no longer leaves the
Navigator staring at waiting prose when a model window is already known.

Automated coverage pins the context reading vocabulary, model-switch cache semantics,
post-compaction estimates, fresh-Conversation estimation, bounded follow-up reads, footer
rendering, stream projection and Rust context extraction.
