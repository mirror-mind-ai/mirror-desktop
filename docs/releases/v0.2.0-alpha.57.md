# v0.2.0-alpha.57 — A Save That Cannot Hold the Application Hostage

**Date:** 2026-10-27

## Highlights

- **A turn can no longer sit in *Finishing* for minutes because Mirror stopped answering.** The save gives up after 30 seconds, and the rest of the application stays usable.
- **Nothing is lost when that happens.** The turn stays on this machine and is delivered again; Mirror recognises a repeated message instead of storing it twice.
- **The next time Mirror fails to answer, it will say why.** Its own error output is kept in a small local record, without the content of any conversation.
- **When the save is stopped, everything it started is stopped too**, so nothing is left behind still holding Mirror's database.

## Where We Started

On 2026-10-22 a turn stayed in *Finishing* for eleven minutes.

The answer had arrived. What hung was the last step, which hands the finished turn to Mirror so it
becomes part of the Journey's memory. The application started a Mirror helper for that and waited for
it with no time limit.

That wait would have been an inconvenience on its own. It became a freeze because of where it
happened: the save holds a lock that most of the application's native actions share, so they run one
at a time. While the helper hung, loading a conversation, opening another one, and every button that
offered a way out all joined the same queue. The ways out were drawn on screen and did nothing.

After a restart, recovery delivered the very same turn in under two seconds. The cause of the hang is
unknown, because the helper's error output was thrown away.

## What Changed

The Mirror helper now runs under a deadline of 30 seconds. Across more than a thousand saves recorded
on this machine the slowest took under eleven, so the limit leaves ample room for a slow day and
none for a hang.

Three details decide whether that limit is real:

- **Stopping the helper stops everything it started.** The helper launches a second process to do the
  work. Stopping only the first, which is what a simple timeout does, was measured to leave the second
  one running — still holding the connection the application waits on, so the freeze would have
  returned one level down. The helper now runs in its own group, and the deadline stops the group.
- **Sending the turn to the helper is inside the deadline.** A large turn used to be written to the
  helper before the clock started; a helper that never read it would block that write forever.
- **Reading the answer is inside the deadline.** A helper can finish while something it left behind
  keeps the answer open; the deadline covers that wait as well.

When the deadline passes, the save reports an ordinary failure. Recovery already repeats ordinary
failures, and Mirror stores a turn in one step and recognises a repeat, so trying again is safe.

The lock itself is unchanged. It exists so that native actions do not interfere with each other; the
fix bounds what may be done while holding it.

## Conscious Exclusions

- **Why the helper hung is not known, and this release does not guess.** It records the helper's own error output so the next occurrence can say.
- **Three other waits without a limit remain, and are named rather than hidden.** One sits on a rare repair path inside this same save, so in that case the worst case is still unbounded.
- **The shared lock is not changed**, and neither is how often or when a failed save is retried.
- **Nothing on Mirror's side changes.**

## What We Learned

**A timeout copied from a place where it is correct can be wrong where it lands.** The application
already had one, for voice transcription, and it stops only the process it started — right there,
because that process does the work itself. Copied here, it would have passed every simple test and
left the real worker running. The difference was found by trying it with the actual helper rather than
by reading the code.

**A deadline is only as good as the first thing that can wait before it.** The plan bounded the wait
for the helper to finish. Building it showed two other waits in the same few lines — one before the
clock started and one after the helper had finished — and either would have reproduced the freeze
behind a timeout that looked correct.

**A test that can only pass proves nothing.** The test that the whole process group is stopped sits
next to one that shows a leftover process surviving when only the first is stopped, and the fix was
removed on purpose to confirm that exactly those tests then fail.

## Next Horizon

This cannot be provoked, so it is checked continuously. From this release, every save is timed, and a
helper that runs well past 30 seconds refutes it. A long save time on its own does not: that number
also includes waiting in line behind other actions, so it is read together with the new failure
record.

The first provider refusal since the previous release is still awaited. It should name itself on the
spot, with the application left open.
