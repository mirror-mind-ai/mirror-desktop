# v0.3.0-alpha.8 — No More Keychain Prompts

**Date:** 2026-11-02

## Highlights

- **No more login password prompts.** The OpenRouter key Mirror's context uses is kept in a file of
  the app's data folder that only your user can read. Your key in the Keychain is carried over
  once: you may see one last prompt after updating; allow it, and it is the last.
- **The key is still never shown.** The screen learns only whether a key is kept and how its last
  check went. Removing it in Settings removes the file.
- **Still Intel only, and not signed.**

## Where We Started

The macOS prompt for the login keychain's password appeared all the time. Every turn read the key
from the Keychain to ask for Mirror's context, and the learning run read it again every ten
minutes. Mirror Desktop is not signed yet, so the Keychain has no identity it can remember, and
"Always Allow" could not hold, least of all across updates.

## What Changed

The key moved to `openrouter-key.secret`, created owner-only (`0600`), written whole and renamed
into place, holding the key and nothing else. With that file kept, the Keychain is never asked.
Without it, the Keychain is asked only whether an item exists, which needs no password; an existing
item is read once, written to the file and removed.

## What Does Not Change

The same Mirror core and the same Pi as v0.3.0-alpha.7. Provider sign-ins stay where Pi keeps them.
Mirror Desktop 0.2 is not offered.

## Conscious Exclusions

- **The Keychain is not used while the app is unsigned.** When Mirror Desktop is signed, the
  Keychain can be the place again.
- **No signing, notarization or Apple Silicon build** yet.

## What We Learned

A safe place an app cannot be recognized by is a door that asks every time. Until the app has an
identity, the protection that holds is the one the file system gives its owner.

## Next Horizon

The composer: keeping what you type while a turn starts, giving back a message whose turn was
cancelled, and lighter typing.
