# v0.2.0-alpha.20 — Model Intents and Response Attribution

**Date:** 2026-09-26

## Highlights

- Introduces Model Intents: a Navigator-authored layer above the Pi catalog.
- Names each intent in your own language, edited in Settings → Agent.
- Switches models in one gesture from the Composer footer, without leaving the conversation.
- Attributes each past response to the model that produced it, drawn forward where the model changed.
- Stops a global busy flag from blocking model preferences everywhere; a run in one Journey no longer disables the model surfaces in every other one.
- Records the model each run started with so the interface can name the live turn and distinguish it from the next.
- Says on the footer what an intent binds beneath the label, without hiding the mechanical layer.

## Where We Started

The Composer told the truth about which model was in force, but only in the
vendor's vocabulary. `openai-codex/gpt-5.5` does not say *for everyday tasks*
and nothing in the product let the Navigator say it either. Switching models
opened a modal with two coupled selects, so the frequent decision cost a heavy
interaction. And the transcript, once a response was recorded, gave no way to
tell which model had produced it.

Underneath sat a smaller problem that made the surface less honest than it
could be. Any Journey running anywhere disabled the model surfaces everywhere,
because `runtimeBusy` combined every lease in the global registry. And once a
turn was live, the interface had no way to distinguish the model it started
with from the model just selected for the next one, since the run did not
carry its own model.

## What Changed

**Model preferences no longer wait on unrelated work.** The global block is
gone from every model surface — the Composer footer entry, `Save global
defaults`, `Restore Mirror Desktop defaults`, `Use model for this Journey` and
`Use global defaults`. Only a settings write already in flight blocks them now.
Each run records the model it started with, so a new selection during a live
turn is marked as reaching the next message, naming the model the running turn
continues on.

**Model Intents introduce a second semantic level above the catalog.** In
Settings → Agent you name the configurations you reach for — *Para tarefas
cotidianas*, *Para as implementações mais difíceis* — and each intent binds a
model and a thinking level once, at configuration time. Selecting an intent
later cannot demote thinking silently because there is nothing left to resolve.

The store lives in its own `model-intents.json`, deliberately outside
`agent-settings.json`. That file validates by exact key allowlist as a
secret-exclusion guard, and its value rule admits neither spaces nor accents,
so it cannot hold a label a person would actually write.

The Composer footer opens a menu with the intents in your order, followed by
`Use global defaults` and `Open full selector…`. When an intent matches the
Journey's effective profile, the footer names it; the model and thinking level
behind it stay reachable in the menu as always-visible secondary text and, in
the compact footer, through the accessible name so the disclosure is not
mouse-only. Selecting an intent performs exactly the Journey override the
dialog already writes, so scope and persistence are unchanged.

**Each past response now names its model.** The Pi transcript authority has
recorded `provider` and `model` on every assistant message all along; the
Desktop was throwing them away. The surface projector collects them into a
derived map keyed by assistant message id, on the precedent CR077 set:
re-derived at every reconstruction, outside the persistence whitelist, so Pi
stays authority, storage carries no duplicate and Conversations that already
exist gain the attribution without migration. Each answer shows the model
beside `AGENT`, drawn forward only where the model changed from the previous
attributed answer. A turn that just finished, and is not yet in the Pi session
the surface last read, is covered by the model captured on the run.

## Conscious Exclusions

- The transcript names the model, not the Model Intent. Intents are a living vocabulary; a stable history has to name what actually produced each answer, and thinking level is not recorded on the Pi assistant message so an intent cannot be reconstructed from history anyway.
- No usage or cost is surfaced per response, though Pi records both alongside the model; that belongs to CR079.
- No reordering of intents by drag; the up/down arrows in Settings serve for now.
- No pinning of intents to Mirror operating modes, and no automatic selection. The Navigator chooses.
- No change to Pi JSONL, the turn journal, the outbox schema, cancellation semantics, native lease lifecycle or Mirror Core.
- Switching the model still blanks the Composer's context usage until the next turn re-establishes stats under the new label; that display is CR079 territory.

## What We Learned

The mismatch between how Model Intents were captured and how they came out is
the story of the release. The original CR asked to *replace the modal with an
inline picker*. The investigation that followed exposed the deeper problem —
the vendor vocabulary — and a Navigator-authored semantic layer became the
answer. That reframe only happened because the previous release had taught us
to treat a cosmetic complaint as evidence, not as noise. It was the same
posture that surfaced CR087 out of a flicker.

Two smaller lessons showed up in homologation. A placeholder that suggests a
Portuguese label in an English UI contradicts a capability whose whole point is
the Navigator's own vocabulary; it was removed rather than translated. A hover
recolour with no honest cross-theme rule was patched once and then removed
entirely, because the pointer already signals interactivity and the recolour
was habit, not need.

## Next Horizon

CR089 asks whether the Conversation may hold a partial answer that Pi's
transcript will never hold; the authority question is still open. CR079, the
context-stats gap between the terminal and the Desktop, is the natural
neighbour to the attribution work in this release — the same Pi entries carry
`usage` and `cost` alongside the model. Beyond RS021 sits the CR088-shaped
question of ordering intents by drag rather than arrows, once the menu has
lived long enough to know whether the ordering matters at all.
