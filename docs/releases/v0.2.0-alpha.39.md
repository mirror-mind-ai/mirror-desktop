# v0.2.0-alpha.39 — The Answer Survives the Restart

**Date:** 2026-10-06

## Highlights

- A turn interrupted by a machine restart and then continued now **settles**, instead of leaving the Journey permanently stuck in `Finishing`.
- The answer the agent produced after you continued is **recovered** — shown in the conversation and delivered to Mirror.
- Recovery recognises an interrupted run for what it is, rather than refusing to decide and leaving the record untouched forever.
- A run that may still be alive is **left alone**, not declared dead: the fix narrows a refusal rather than removing it.
- Replayed read-only over the production store: the two stranded records resolve, two unrelated ones stay exactly where they were, and nothing that previously recovered stops recovering.

## Where We Started

This release exists because of one real failure, reported while it was happening.

A computer restarted in the middle of a turn. Desktop came back and correctly showed the turn as interrupted. The Navigator sent `continue`. The agent resumed, worked for about eighty seconds, and finished cleanly — and Desktop never noticed. The Journey showed `Finishing` from that moment on, with an empty answer bubble, and would not accept new work.

The answer was not lost. It sat in the session file: 952 characters, closed properly, ending in *"Recuperação concluída."* Desktop simply had no way to connect it to the turn it belonged to.

The mechanism was not a bug in the ordinary sense. Recovery compares the runs a Journey never saw finish against the completed exchanges in the agent's session, and recovers a run when it can match the two one to one. A completed exchange is the only thing it could see. A run killed by a power cut produces no completed exchange, so the thing the restart left behind was invisible to it — before `continue` was even sent. And after `continue`, the situation got worse rather than better: the agent resumed the *same* session and closed a single exchange covering both runs, so two unfinished runs faced one completed exchange. Two against one never matches, so recovery refused — correctly, by its own rule — and would have refused on every reload, forever.

This was known. When the previous release shipped, this exact limitation was written down as debt: recovery cannot resolve a case where the number of runs and the number of exchanges disagree. It was recorded as unfixable without information recovery did not have. That turned out to be wrong, and the Navigator's stuck Journey is what proved it.

## What Changed

### Recovery now matches runs to requests, not to answers

The missing information was never missing. Every run that got far enough to contact the agent wrote one thing into the session: **your request**. That exists whether or not the run survived to produce an answer.

Recovery now pairs unfinished runs against unanswered requests, in the order the runs started. Each run then gets the verdict the session genuinely supports:

- **Your request was answered** — the run is recovered with that answer, exactly as before. Nothing about the normal path changes.
- **Your request was never answered, and you have since sent another** — that run is over, and it is recorded as interrupted. A new request can only appear after the previous process ended, so this is evidence rather than inference.
- **Your request was never answered and nothing follows it** — nothing is decided. The run may still be working.

The last case matters more than it looks. While this change was being built, exactly that situation appeared in another Journey: an unfinished run, two minutes old, almost certainly still running. A rule that treated every unanswered request as a dead run would have declared live work dead. Desktop now names that state and leaves it alone; your next request in that Journey resolves it.

### Interrupted turns can finally be recorded as interrupted

Marking a turn interrupted was always permitted, but only the app window could do it — and a machine restart destroys the window along with the run. Nothing was left to notice. Recovery can now record it, which is what allows a restart to be cleaned up at all.

### Everything that refused before still refuses

Where the runs and requests cannot be matched one to one, or where the recorded times disagree — a request older than the run that supposedly made it, an answer completed after the next run had already started — recovery still declines and leaves the record exactly where it is. The change makes recovery able to decide more cases. It does not make it willing to guess.

## Conscious Exclusions

**The `Finishing` label itself is unchanged.** A turn that cannot move forward still describes itself as `Finishing`, which is the wrong word for it. This release removes the cause in the case we found; it does not fix how the Composer talks about a turn that is stuck for some other reason.

**The interrupted turn's own conversation record is left incomplete.** When a restart-and-continue is recovered, the continued turn settles fully. The original interrupted turn keeps an unfinished internal record. Nothing surfaces it, and repairing it correctly is separate work.

**Nothing was repaired by hand.** The stranded Journey was left untouched. Editing the stored record directly would have destroyed the only evidence of the failure, and would have written in by hand precisely the guess this change refuses to make in code.

**Nothing is written backwards into Mirror.** A turn recovered by this release is delivered normally. Turns lost before it are not retroactively inserted.

## What We Learned

**A refusal can be correct and still be a defect.** Recovery was reasoning soundly about the only evidence it had been given. The failure was in what it had been allowed to look at.

**Debt recorded honestly came back usable.** The previous release wrote this limitation down, including the belief that it could not be fixed. When it stranded real work, the diagnosis was already on paper — and the part that was wrong was identifiable because it had been stated plainly.

**The conservative branch was not caution, it was a measurement.** The decision to leave a trailing unanswered request undecided came from finding a live run in that exact state during the work. Without that observation the rule would have been one line simpler and would have killed a running turn.

**A fix verified against real data told us how little it changed.** Replayed over every unfinished run in the store, the new rule decides the two that were stuck and leaves the rest untouched. Nothing that used to recover stopped recovering — the old rule had resolved none of them.

## Next Horizon

The stranded Journey is the verification. Opening it on this release should show the recovered answer in the conversation and deliver it to Mirror — observable, and not yet observed. Beyond that: a Journey's first turn still fails an internal step that recovery silently repairs, and a recovered turn still writes no record of having been recovered, so a repaired failure and a real one look the same from outside.
