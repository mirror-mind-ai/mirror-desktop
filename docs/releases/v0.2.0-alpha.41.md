# v0.2.0-alpha.41 — The Form Stops Promising What It Cannot Do

**Date:** 2026-10-07

## Highlights

- **Project path changes now work.** Setting, changing or clearing a Journey's project path from Edit Journey succeeds.
- **Name and description no longer fail on Save.** They are shown as Mirror holds them, with one line explaining that changing them needs a newer Mirror.
- Saving without having changed anything closes the dialog quietly, instead of writing or complaining.

## Where We Started

**Save changes** in Edit Journey had never worked. Not since the dialog gained those fields on 2026-09-02. Every press failed with:

> Mirror rejected the Journey mutation: unsupported_operation.

The message named nothing you could act on. Worse, Journey appearance lives in the same dialog and applies immediately with its own confirmation — so if you changed an image and then pressed Save, the failure looked like it belonged to the image. That misreading is on record: it produced a Change Request about Journey images that was investigating the wrong thing entirely.

## What Changed

### The path works

A Journey's project path is the one canonical field Mirror can change today, and the Desktop had never actually wired it. Now it does: give a Journey a path, point it somewhere else, or empty the field to remove it. Each is submitted as the operation Mirror expects, with the same verification and the same receipt every other Journey change already gets.

### The fields that cannot change say so

Name, description, Journey ID and slug are shown read-only, with one note:

> Name, description, Journey ID and slug are shown as Mirror holds them. Mirror has no canonical update operation for them yet, so they cannot be changed here.

The dialog's summary no longer claims it will update your name and description. It says what it will do.

### Nothing offers an impossible action anymore

The refused operation was not merely left unused — it was removed from the Desktop entirely, so it cannot be sent by any path, by mistake, from anywhere.

## Conscious Exclusions

**Renaming is still not possible, and this release does not add it.** Mirror itself needs an operation it does not have in the version you are running. Showing the field read-only is honest, not a fix.

**No local-only rename.** The Desktop could store its own name for a Journey and show that. It will not. Mirror owns Journey identity, and a second name kept privately on one machine would look like it worked while quietly disagreeing with everything else that reads Mirror.

**Appearance stays on this device.** Unchanged by this release.

**Nothing was loosened to make the path work.** The two path operations ride exactly the same verification as everything else. A Journey that changed in Mirror while your form was open still gets the handling added in alpha.40.

## What We Learned

**A feature can fail for five weeks without being broken.** The Desktop's request was correct and well-formed. What was missing was on Mirror's side, written the same day, and never released. The Desktop was asking for something real that had simply never shipped — which is a very different problem from a bug, and needs a release rather than a repair.

**Where you test decides what the test means.** This change was nearly validated in the development channel, which turned out to run a *different* Mirror than the one you use — one where the broken Save works fine. That test would have passed and concluded there was nothing wrong, against a failure already seen in daily use. Both Mirrors even report the same version number.

**Three tests were pinning the broken behavior.** They had been written to prove the Desktop sends a proper update, and what they actually guaranteed was that it keeps sending something that cannot succeed. Each was re-aimed at what remains true rather than deleted, which is the only way a safety net survives being wrong.

## Next Horizon

Name and description need a Mirror release, and everything that release requires is now written down and verified so it does not have to be re-investigated. Nearer term: knowing which Mirror a given channel is really talking to, rather than trusting a version number that can be identical across two different contracts.
