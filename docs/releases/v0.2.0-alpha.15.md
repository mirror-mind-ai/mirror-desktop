# v0.2.0-alpha.15 — Truthful Provider and Model Surfaces

**Date:** 2026-09-22

## Highlights

- Restores visibility for messages rejected before the agent starts: the draft returns to the Composer and the `Message was not sent` banner carries the provider/Pi reason.
- Loads globally installed Pi provider extensions explicitly while keeping project-local extension discovery disabled, preserving the single conversation-writer invariant and making Claude Bridge models runnable in Desktop.
- Marks offered models unavailable only when an invocation-shaped catalog read proves the send cannot resolve them; unavailable options remain visible but disabled with a reason.
- Persists bounded provider error text for mid-run process deaths and surfaces it in the interrupted-turn notice when exact durable evidence exists.
- Removes dead `--provider`/`--model` literals from the editable arguments template and shows the effective model, thinking level and source in Settings.

## Where We Started

After Alpha.14, ordinary multi-turn synchronization was finally quiet, but provider/model failures were still hard to trust. A model from `claude-bridge` appeared in Settings, failed immediately in Desktop because extension discovery was disabled, and initially produced no visible explanation. At the same time, Settings showed raw argument literals that looked authoritative even though every send stripped and replaced them from the selected agent profile.

The failure was not one bug. It was a set of surfaces telling partial truths: the Composer could lose the reason for a rejected send, the catalog could offer models the invocation could not resolve, interrupted attempts could hide a provider error, and Settings could display command text that the runtime intentionally ignored.

## What Changed

Pre-agent rejection is now a first-class presentation state. The app records an unsent-draft notice per Journey at every pre-agent rejection site and clears it on the next admitted send. When Pi emits a specific provider warning before the process exits, the notice prefers that cause over the generic exit-status symptom.

Desktop no longer treats `--no-extensions` as a blanket loss of providers. It keeps discovery disabled, so project-local writers such as `mirror-logger` stay structurally excluded, then passes explicit `--extension` entries for the globally installed Pi set resolved from `~/.pi/agent`. Installing or removing a Pi package remains the curation surface; Desktop mirrors that global set without a second allowlist.

Model availability now comes from the same question the send asks. The Settings catalog is compared with an invocation-shaped catalog read carrying `--no-extensions` plus the resolved global extension entries. Models offered by discovery but absent from that invocation read remain listed, but disabled and explained. Unknown models still pass through to Pi: this feature prevents only failures that are knowable before send.

For failures that happen after the agent has started, the turn journal can now retain a bounded provider failure line from stderr when the process dies. The interruption notice quotes it only while that failed run remains the latest durable outcome for the thread. Abrupt deaths without provider evidence stay generic rather than inventing a cause.

Finally, Settings stops presenting dead model literals inside `Arguments`. The template is stable arguments only, and the card now names the effective model, thinking level and whether the value comes from the global default or a Journey override. If a user types `--provider`, `--model` or `--thinking` anyway, an inline note explains that the agent profile will replace those flags at send time.

## Validation

- Navigator homologation on Dev for CR070: the invalid Claude Bridge selection produced a `Message was not sent` banner with the provider reason, cleared on a valid-model send, and ordinary turns stayed clean.
- Navigator homologation on Dev for CR072: `claude-bridge/claude-opus-5` executed end-to-end once global Pi extensions were loaded explicitly.
- Navigator homologation on Dev for CR071: no false unavailable indicators appeared after CR072 made every offered model resolvable; the unavailable path is covered by invocation-shaped catalog tests.
- Navigator homologation on Dev for CR054: an abrupt killed process recorded `process_died` without fabricating a provider reason; positive provider-error rendering is covered by bounded stderr-capture tests because a mid-generation quota failure cannot be forced deterministically.
- Navigator homologation on Dev for CR053: Settings showed the effective model/source, warned about profile-owned raw flags, and ordinary sends used the selected model.
- Complete suites at preparation time: frontend tests, Rust tests, TypeScript/Vite build, and roadmap consistency.

## Conscious Exclusions

- This release does not retry providers, switch providers or models, or infer alternate credentials.
- This release does not implement automatic stall detection for long provider silence; retesting showed network loss waits and resumes correctly, so CR073 was dismissed.
- This release does not change Pi JSONL transcript authority or the single Desktop conversation writer contract.
- This release does not mutate Mirror Core, production memory, Journey data, authentication state or provider credentials.
- This release does not promote stable distribution, notarization, app-store delivery or Windows/Linux packaging.

## What We Learned

The invariant was not “no extensions.” It was “no second conversation writer.” Once stated that way, provider extensions could return without reopening Mirror persistence risk: global entries load explicitly, project-local discovery stays off, and writer-shaped extensions remain excluded.

A truthful UI is layered. Prevention handles the models known not to resolve; pre-agent failures return the draft with the exact reason; terminal failures quote only durable provider evidence; unknown cases remain with Pi, rather than being guessed from the renderer.
