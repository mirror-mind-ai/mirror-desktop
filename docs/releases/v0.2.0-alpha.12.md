# v0.2.0-alpha.12 — Provider Error Composer Release

**Date:** 2026-09-19

## Highlights

- Releases the Composer after a terminal provider error settles as an interrupted attempt.
- Keeps the preserved native attempt and interrupted-attempt notice unchanged.
- Prevents stale recovery state from blocking the next user turn after provider exhaustion or similar terminal failures.
- Records the post-alpha.11 Workbench reconciliation for CR052, CR038, CR037 and CR055.
- Keeps CR053 and CR054 captured for future work rather than quietly broadening this corrective release.

## Where We Started

Alpha.11 improved Conversation navigation and close safety, but real use exposed a narrower failure after provider exhaustion. When Pi reported a terminal provider error such as a ChatGPT usage-limit failure, Mirror Desktop correctly preserved the attempt as interrupted evidence. The visible Composer, however, could remain blocked by stale recovery state even after the terminal process had finished.

That left the Navigator in an awkward position: the transcript authority and preservation model were doing the right thing, but the writing surface still behaved as if recovery work were active.

## What Changed

When a terminal provider failure follows the interrupted-settlement path, Mirror Desktop now clears the selected Journey's blocking turn-journal record and recovery busy/error state after the interrupted settlement and durable lease cleanup complete.

The ordering matters. The app does not release the Composer before preserving the interrupted attempt and cleaning up the terminal lease. It only clears the local blocking state after the exact interrupted-settlement route has run.

The Refinement Workbench was also reconciled against the already-published alpha.11 line. CR037 and CR038 are recorded as done after Navigator validation, CR052 is recorded as shipped in the alpha.11 code line, and CR055 is recorded as the corrective implementation delivered by this release candidate.

## Validation

Local validation covered the corrective path and the reconciled release line:

- Focused runtime integration test proving interrupted settlement clears Composer blocking only after durable lease cleanup.
- Application theme contract tests confirming the light-theme generation-ready notice correction remains present.
- Composer draft integration tests protecting the alpha.11 coalesced persistence behavior.
- Complete frontend test suite.
- Frontend production build through `tsc && vite build`.
- Roadmap consistency and whitespace checks.

## Conscious Exclusions

- This release does not surface the provider terminal error text in the GUI; that remains CR054.
- This release does not redesign Settings argument display or effective model explanation; that remains CR053.
- This release does not retry provider calls, switch providers, consume fallback models or infer alternate agent credentials.
- This release does not merge Desktop transcript projections with Mirror terminal continuations.
- This release does not promote stable distribution, notarization, app-store delivery, Windows/Linux packaging or production Mirror data mutation.

## What We Learned

A terminal provider failure can be correctly preserved and still leave the user-facing writing boundary stale. The fix is not to retry or reinterpret the provider error. The fix is to make local blocking state follow the exact native terminal evidence after preservation has completed.

This keeps the core RS018 rule intact: Pi JSONL remains the transcript authority, interrupted attempts remain evidence, and Desktop affordances should reflect native inactivity rather than stale projection state.

## Next Horizon

Continue with the remaining RS016 captures deliberately. CR054 should make provider terminal errors visible in the GUI without violating the no-implicit-retry rule. CR053 should clarify the effective model in Settings without exposing misleading arguments. Release publication, endpoint upload, Git tag, GitHub prerelease and stable-channel promotion remain separate explicit Navigator decisions.
