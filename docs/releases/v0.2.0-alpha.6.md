# v0.2.0-alpha.6 — Active Steering and Responsive Conversation History

**Date:** 2026-09-13

## Highlights

- Sends bounded text corrections to the exact active Pi turn without cancellation, replay, a second process, or another assistant placeholder.
- Preserves FIFO Steering order and distinguishes transport acceptance from authoritative Pi application evidence.
- Repairs persisted false-negative Steering outcomes when exact Pi user-entry evidence later proves application.
- Presents corrections as compact user addenda between the originating user message and its single Agent turn.
- Keeps composer typing outside the complete historical transcript render path.
- Indexes immutable turn, Steering, activity, and terminal-action evidence for long conversations.
- Materializes collapsed historical operations and system surfaces only when the Navigator opens their disclosure.
- Adds deterministic 1,000-message and 10 MB scale coverage without copying production conversation content.

## Where We Started

Mirror Desktop could run one trustworthy dedicated Pi process per turn, preserve semantic Agent Actions, System Surfaces and Agent Comments, and recover exact terminal evidence. Once a turn started, however, the Navigator could only wait or cancel. A correction typed during an active response could not enter that same Pi run under the desktop's exact Journey and session authority.

Continued alpha use also exposed a second continuity limit. The `mirror-desktop` Journey had grown to 718 messages and a 5.09 MB generation projection. Because composer draft state and the inline full-history message map shared the top-level App render, every keystroke repeated historical surface extraction, semantic projection, Markdown parsing and action grouping. Returning to the Journey also constructed more than five million characters of static markup, including operation bodies hidden inside closed historical disclosures.

## What Changed

Mirror-mediated execution now uses Pi's LF-delimited JSONL RPC mode and keeps the exact child stdin writable until `agent_settled`. Tauri correlates `prompt`, `steer` and `set_steering_mode` responses, configures Pi's `one-at-a-time` Steering policy and admits a correction only when Journey, thread, Mirror conversation, generation, Pi session, run, turn, Harness messages and registered process all agree. The registry releases its global lock before waiting on the child or writing stdin.

A successful Steering RPC response records `accepted`; it never claims application. Exact Pi user entries establish `applied`, including corrections followed by intermediate tool use. Stable request identity and sequence preserve duplicate-text FIFO ordering. Cancellation, failure, process death, settlement and restart terminalize unconsumed requests honestly. Restart reconciliation can repair an earlier `terminally_unconsumed` result when authoritative session evidence proves the correction was consumed.

The composer sends active-run text through Steering without staging another run, message pair, invocation slot or assistant placeholder. Corrections render as compact user addenda after the originating user box and before the one Agent box. Persisted conversation schema `0.9.0` adds bounded Steering evidence while retaining compatibility with earlier generation projections.

Long-conversation presentation now lives behind a memoized `ConversationTranscript` boundary. Draft-only App updates retain stable transcript props and no longer execute historical message projection. Rows are independently memoized so active runtime updates refresh changed messages rather than the immutable history. Conversation-revision indexes replace repeated per-message scans for turn ownership, Steering and exact terminal action evidence while preserving the same authority checks.

Historical Agent Comments and truthful action/surface counts remain immediately visible. Closed historical disclosures no longer mount their operation arguments, outputs or system surfaces; opening one materializes the complete exact evidence and closing it releases the heavy subtree. Action groups are reused instead of projected twice. In the diagnosed production shape, initial static markup fell from 5,518,018 to 1,854,469 characters, a 66.4% reduction. A generated fixture exercises 500 turns, 1,000 messages, eight Steering records and at least 10 MB of terminal projection data without retaining private content.

## Conscious Exclusions

- Expanded concurrent Journey turns, persona spaces, multiple conversations per Journey and voice composition remain planned CV-008 Delivery Stories.
- Steering remains text-only and excludes attachments, images, voice, editable follow-up queues, templates, skills and cross-Journey targeting.
- Long-history correction does not truncate messages, paginate or virtualize the transcript, segment persistence, automatically split conversations or restart generations.
- Pi remains the sole active-context and automatic-compaction authority; compaction is not treated as desktop transcript deletion or UI optimization.
- Persisted exact history, terminal action evidence, Steering evidence, Mirror records and restart semantics remain intact.
- Apple Developer ID signing and notarization remain unavailable and are not claimed by updater signing.
- No stable updater channel, automatic promotion or unlimited concurrency is introduced.

## What We Learned

A correction channel is trustworthy only when transport acknowledgement and model-visible application remain separate facts. Keeping one Pi process per run made native Steering possible without weakening lifecycle authority, but only exact session evidence could close the truth gap between an accepted RPC command and a correction actually entering the agent's continuation.

Conversation continuity also has distinct durable, visual and model-context dimensions. Preserving complete history does not require reprocessing or mounting all of it for each keystroke. Pi compaction protects the bounded model context while the desktop must independently bound presentation work. Stable render boundaries, indexed evidence and lazy historical detail restore responsiveness without deleting the record or inventing a second context authority.

## Next Horizon

Observe active Steering and long-history behavior through the alpha channel, then refine CV-008.DS-002 for bounded concurrent Journey turns. CV-008.DS-004 now carries the broader contract for multiple conversations, incremental historical materialization, durable segmentation and the distinction between complete visible history and compacted Pi context. Those capabilities should build on this release's exact authority and bounded rendering seams rather than reopening them.
