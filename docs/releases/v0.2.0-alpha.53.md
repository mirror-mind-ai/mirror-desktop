# v0.2.0-alpha.53 — One Finishing, and Every Exit Reads It

**Date:** 2026-10-17

## Highlights

- **Every path to *Finishing* now has the same exits.** The sentence that explains a long wait, the button that ends it, and the notice that recovers a finished answer all read one derived value.
- **A turn that freezes before settlement begins is now noticed while you watch.** Previously the notice could only fire while the surface said *Working…*, which is never the state a frozen turn shows.
- **The wait is counted from a durable moment.** For a turn whose answer was committed but never projected, the count starts at the provider's own commit timestamp rather than at a renderer clock that resets.
- **The *Stop waiting* button acts even when the runtime has already forgotten the turn.** It used to return silently in exactly that state.
- **The refusal reason "not finishing" can no longer be returned while the screen says *Finishing*.** An exhaustive guard now proves it across every input the composer accepts.

## Where We Started

The previous release recovered a stranded answer on the next launch and shipped a notice that would
recognise the condition live. The same morning, the Navigator's own conversation froze at *Finishing*
on that release, was force-quit, and nothing had been drawn. Asked whether the explanatory sentence
from the release before had appeared, the answer was that it had not.

Both notices were correct in isolation. *Finishing* reaches the screen through the settlement flag or
through a conversation whose provider body is committed and whose projection is not. The settlement
flag is set only inside the settlement path. When the journal freezes before settlement, that path
never runs, the flag is never set, and the composer says *Finishing* through the second source —
where the exit logic saw no finishing at all and the stranded check saw no streaming turn.

The guard written one release earlier to stop a refusal being silent by default had listed that very
refusal as deliberately silent, on an assumption this occurrence disproved.

## What Changed

### One derivation

The composer's finishing is derived once, from the status it actually draws, naming its source and
the moment the wait can honestly be counted from. The settlement-abandonment offer, its presentation,
the notice that draws it, and the stranded-turn predicate all read that value in place of the runtime's
owner phase. Two derivations that could disagree became one that cannot.

### A countable start for the second source

The settlement source keeps the settlement's own clock. The reconciliation source dates the wait from
the provider's commit, a timestamp the conversation already carries durably. One path — a thread not
yet ready — has no commit to date from and is left uncounted on purpose, rather than counted from an
invented moment.

### The stranded check runs while finishing

The predicate and its fifteen-second poll now run while the composer is finishing, not only while it
streams. The reason previously named `not_streaming` is renamed `not_live`, because the old name had
become false of what the gate checks. When the runtime entry is already gone, the journal's own newest
unfinished record on the thread supplies the run to compare against.

### The act proceeds without a runtime identity

Stopping the wait no longer returns early when the runtime has no identity for the turn — which the
reconciliation source always leaves it without. Only the flag-clear depends on the identity; the
durable convergence runs regardless.

## Conscious Exclusions

- **No change to what the native terminal path writes, and none to the attribution rule.** The
  recovery shipped in the previous release is field-verified twice and recovers these turns on relaunch.
  This release is about the wait, not the repair.
- **No treatment of the one uncounted path.** A thread not yet ready shows *Finishing* with no start
  to count from and stays silent by design; the stranded notice does not depend on the count and is
  unaffected.
- **The explanatory sentence at sixty seconds is now verified by fixture, not by the field.** The
  recovery notice fires at roughly ten seconds and will be acted on first. This is accepted and recorded
  rather than claimed otherwise.

## What We Learned

- **One word on screen with two sources is two states wearing one label.** Every exit was keyed to the
  mechanism that happened to record the state, not to the state itself.
- **A guard that enumerates its author's assumptions passes while the assumption is false.** The
  allow-list that made a refusal "deliberately silent" is now backed by an exhaustive enumeration over
  every input, so the listing is proved rather than believed.
- **A gate on "streaming" is closed in exactly the state that says "finishing".** The composer returns
  *working* whenever streaming is true, so a surface reading *Finishing* is itself proof that the old
  gate could not open.
- **An offered control must act.** The button was offered in a state where its handler returned
  silently, which is a label that lies.

## Next Horizon

- **Field falsifier on this release:** the next turn that freezes at *Finishing* should draw *This turn
  has already finished* with a Recover action about ten seconds after the provider's commit. If a turn
  freezes and nothing is drawn within a minute, the change is refuted, not merely unverified.
- **Record which notice was on screen.** Nothing durable does, so a report of "I saw nothing" cannot be
  told from a notice that was drawn and not noticed. Every other claim in this theme was settled from an
  artefact; this one could not be.
- **The recovery's own refusals are still written to a file nothing reads.** The same criterion, one
  layer down.
