# v0.2.0-alpha.2 — Sidebar Version Label and Alpha Build Contract

**Date:** 2026-09-09

## Highlights

- Moves the persistent Mirror Desktop version/update affordance from the chat header into the sidebar brand area.
- Shortens prerelease labels in the UI, so `0.2.0-alpha.2` appears as `0.2.0-a2`.
- Presents the sidebar label as discreet linked text: `Version: 0.2.0-a2`, with `update` highlighted only when a newer release is available.
- Keeps the update popover and Settings dialog above the sidebar and main surface.
- Adds `npm run alpha:build` as the canonical local signed alpha build command.
- Keeps the macOS site download stable at `https://updates.mirrormind.sh/mirror-desktop/alpha/downloads/macos/latest.dmg`.

## Where We Started

The first governed alpha proved that Mirror Desktop could publish a signed updater lane and a stable public download endpoint. Once the app was opened from the downloaded build, the version label exposed a smaller product problem: the full prerelease string was too loud for a persistent UI surface.

The release process also exposed an operational trap. A generic Tauri build can produce a DMG without the alpha updater overlay, and that artifact is not the correct validation build for the alpha channel.

## What Changed

Mirror Desktop now separates release authority from daily presentation. Package, Tauri, Cargo, updater manifests, release notes, and artifacts keep the full version `0.2.0-alpha.2`. The persistent app UI uses a shorter display label, `0.2.0-a2`, under the stable `Mirror Desktop` title in the sidebar.

The update affordance is no longer a badge-like element in the chat header. It is a small sidebar text link. When an update exists, the word `update` is highlighted with the application accent. The popover includes a clear version line and keeps the preservation boundary visible.

The alpha build ritual is now centralized in `npm run alpha:build`. The command runs the alpha updater preflight, reads the local alpha signing key, builds with `src-tauri/tauri.alpha-update.conf.json`, and verifies the app, DMG, updater artifact, and updater signature outputs.

## Conscious Exclusions

- Apple notarization is not claimed until Developer ID credentials and a notarytool keychain profile are configured.
- No stable or production updater channel is declared.
- The updater still targets application bytes only; Mirror homes, `memory.db`, identity, credentials, Journey content, conversations, app data, and Nautilus Harness state remain outside the mutation boundary.

## What We Learned

A version can be technically precise without becoming visually central. The release record needs the whole name; the user needs a quiet orientation point.

The build path needs the same discipline. Alpha is not just a version string. It is a signed channel, an updater overlay, a key custody boundary, and a set of expected outputs. When those are implicit, the wrong artifact can look correct until startup proves otherwise.

## Next Horizon

The next alpha horizon is to keep tightening the public download and self-update path: validate the site download, validate an installed-app update from the previous alpha, and decide whether notarization becomes required before broader external distribution.
