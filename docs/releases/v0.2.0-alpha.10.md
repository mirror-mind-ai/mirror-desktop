# v0.2.0-alpha.10 — Terminal-Aligned Conversation Continuity

**Date:** 2026-09-18

## Highlights

- Makes the Pi session JSONL the sole authoritative agent transcript for Journey Conversations.
- Rebuilds inactive Conversation surfaces from exact Pi inspection instead of projection or Segment bodies.
- Admits successor turns after native completion without waiting for Desktop projections, journals, Segments, or Mirror delivery.
- Keeps only exact active native occupancy as a blocking condition.
- Treats Mirror synchronization as self-contained, model-free, repairable delivery debt.
- Preserves and explains interrupted native attempts without retrying the provider or blocking the Composer.
- Recovers failed assistant leaves and post-native/pre-delivery termination windows from exact Pi evidence.


## Where We Started

Reliable Agent Access separated local completion from secondary synchronization, but Mirror Desktop still carried several durable bodies that could disagree about what had happened: Pi JSONL, Desktop projections, turn journals, native invocation occupancy, Conversation Segments, Mirror append outbox, and Mirror Conversations. In sustained use, stale projection or Segment evidence could still become operationally louder than the actual Pi transcript.

The terminal model had a simpler authority shape: Pi owns conversation continuity, and Mirror logging is a side effect. RS018 brought the Desktop to that shape while preserving the desktop-specific coordinator features: Journey routing, concurrent execution, visual Conversation surfaces, bounded Segments, explicit repair actions, and release-safe recovery.

## What Changed

Conversation restore and inactive surfaces are now Pi-backed. The app inspects the exact active Pi branch for the selected Journey, thread, generation, and session, then projects visible user/assistant turns from native entries. Desktop projections and Segments remain useful presentation caches, but they no longer define the transcript or block normal continuity when they are stale, missing, or deleted.

Successor admission now follows exact native state. A completed native turn can admit the next message even while Mirror delivery is pending. Historical journals, local projections, bounded Segment manifests, and copied caches do not block successors unless an exact active native invocation is still occupying the Journey authority.

Pre-agent staging is non-authoritative. A user message becomes durable transcript content only after exact native admission. Rejected or failed pre-admission attempts do not leave ghost transcript entries, and provider execution is never repeated implicitly during reconstruction or repair.

Mirror delivery debt is self-contained. Completed Pi-backed turns can materialize durable outbox items with exact Journey, thread, generation, Pi session, entry, and Mirror destination coordinates. Explicit repair replays only Mirror delivery and acknowledgement; it does not call the provider.

Interrupted attempts are visible but passive. When a native user entry is incomplete, or a later failed native assistant/tool leaf proves that the attempt did not complete, the app shows a non-blocking explanation and keeps the Composer available once occupancy is inactive. Successful assistant `stop` or `length` evidence clears the interruption path.

The post-native/pre-delivery fault window now recovers from Pi. If the app closes after Pi durably records a successful assistant but before settlement or Mirror debt materialization, the repair route can adopt exact terminal evidence from an unambiguous unclaimed Pi turn, promote legacy outage debt to Pi-backed debt, deliver it model-free, acknowledge it, and settle the journal without relying on projection message aliases.

## Release-Shaped Acceptance

The acceptance rehearsal used private-data-free isolated DEV app data and disposable Mirror state. It validated:

- a supported-model baseline;
- multiple completed turns while Mirror was unavailable;
- successor admission during pending Mirror debt;
- restoration and exact model-free settlement of Mirror delivery;
- termination after Pi completion and before delivery settlement;
- relaunch without provider retry;
- concurrent Journey turns in separate Pi sessions;
- deletion of copied derived Conversation projection and Segment caches;
- reconstruction from Pi sessions alone;
- exact restoration of ordinary DEV state and no production mutation.

Two real defects surfaced during this acceptance and were fixed before closure: failed assistant leaves are now accepted as interrupted-attempt evidence when exact Pi inspection proves the user remains incomplete, and post-native delivery repair now materializes debt from Pi evidence rather than stale projection identities.

## Conscious Exclusions

- This release does not perform production Flip Podcast recovery; production data remains a separate explicitly authorized operation.
- It does not publish, promote, or mutate Mirror Core behavior.
- It does not make Mirror Conversations authoritative for Desktop continuity.
- It does not retry providers during relaunch, reconstruction, interruption handling, or Mirror repair.
- It does not remove the need for explicit repair actions when Mirror delivery debt remains.
- It does not absorb independent CR038 composer-draft work.
- Apple notarization, stable-channel promotion, Windows/Linux packaging, and app-store distribution remain outside this alpha release.

## What We Learned

The safest continuity model is not “make every durable body agree before continuing.” It is “give every body one authority and one consequence.” Pi owns transcript content. Native occupancy owns active capacity. The journal owns lifecycle evidence. The outbox owns delivery debt. Projections and Segments own presentation. Mirror owns synchronized memory projection.

The release-shaped rehearsal mattered because the hard bugs lived between these boundaries. Unit tests proved the pieces, but the unsupported-provider leaf and terminal-window delivery gap only appeared when the system was exercised as a user would encounter it.

Recovery is also clearer when it is honest about what it can do. A passive interruption notice should not offer a retry button. A Mirror repair should not rerun the agent. A deleted cache should be rebuilt from Pi rather than treated as loss.

## Next Horizon

Use the alpha to validate terminal-aligned continuity under normal work. The next operational decision is whether to perform a separately authorized production recovery for affected existing Conversations, using the RS018 authority model. Release promotion, public distribution, production mutation, and further updater-channel decisions remain explicit Navigator actions.
