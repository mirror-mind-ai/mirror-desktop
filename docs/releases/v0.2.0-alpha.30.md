# v0.2.0-alpha.30 — A Quiet, Responsive Composer

**Date:** 2026-10-02

## Highlights

- Keeps visible Composer text in a memoized leaf, so ordinary keystrokes no longer re-render the Desktop root.
- Preserves durable draft recovery, including voice insertion, Canvas prefill, destination changes, send clearing and failure retry.
- Stops an idle post-terminal recovery cycle that repeatedly reconciled occupancy with no native work to do.
- Keeps Send and New Journey steady while idle and during composition.
- Retains lease reconciliation whenever native occupancy genuinely changes.

## Where We Started

The Composer in a large Journey had become perceptibly slow. Static inspection first found that
each character updated state in the 6,303-line `App` root, despite the transcript boundary from
CR029 remaining memoized. A browser measurement established the mechanism: root-owned keystrokes
crossed the frame budget as the non-memoized sibling tree grew, while a leaf-owned input stayed near
three milliseconds and never rendered the root.

The first Eval homologation showed a second symptom: Send and New Journey flickered even while
nothing was happening. That made the Composer correction impossible to judge alone. The cause was
an older recovery residue: every no-op post-terminal recovery reconciled occupancy, and its own
effect watched the resulting `reconciling` then `known` transition. An idle Journey recovered again
forever.

## What Changed

**The input owns visible composition.** `ComposerDraftInput` is a memoized leaf with its own text
state and an imperative write handle for programmatic changes. `App` retains a ref for semantic
boundaries, a blank flag for control enablement, and the durable draft map outside render state.
Typing updates the coalesced persistence path without asking the root to render. Send and Steering
read the ref only when invoked.

**Programmatic composition remains whole.** Restore, Journey and Conversation switches, voice
transcription, Canvas prefill, clearing after Send and returning a failed request to the Composer
all use the input handle. The existing 750 ms coalesced writer and its blur, switch and close flushes
are unchanged.

**Idle recovery no longer calls itself.** The trailing occupancy reconcile was removed from
post-terminal convergence. A no-op convergence has not changed native occupancy. When convergence
does release a retained lease, its existing lease-release path reconciles occupancy itself; that real
state change may run one bounded follow-up recovery and then settles.

## Validation

The Navigator accepted the rebuilt Eval carrying both corrections. Sustained composition in
`mirror-desktop` was responsive, and Send plus New Journey stayed steady while typing and while
idle. The validation did not claim a new instrumented input-to-paint percentile or CPU benchmark.

Automated gates passed: 215 front-end test files and 1,485 tests, TypeScript checking, production
frontend build, locked Cargo checking, refinement roadmap validation and whitespace validation.

## Conscious Exclusions

- No change to Pi JSONL, Mirror records, journal, outbox, turn authority or send semantics.
- No change to the delivery coordinator, occupancy domain functions, ports or Rust commands.
- No conversation windowing or Segment projection correction; that distinct working-set contract remains CR114.
- No tag, artifact, signing, notarization, updater mutation, push, public release or production installation is created by this preparation alone.

## What We Learned

A stable memo boundary is not enough if unrelated root work is continually re-triggered. The two
corrections have different responsibilities: local input ownership removes per-character root
renders; bounded recovery removes the background root renders that otherwise obscure it. Together,
they restore the ordinary expectation that an idle workspace stays quiet.
