# v0.2.0-alpha.42 — Nothing Waits Forever

**Date:** 2026-10-08

## Highlights

- **A Journey's first turn can finish.** A fresh Pi session wrote a chapter file the app then refused to read, and that refusal failed the whole turn. The turn now completes.
- **`Finishing` has an exit.** After a minute, a **Stop waiting** control appears, releasing the composer so you can keep working without restarting the app.
- **A stuck wait now leaves a trace.** It previously recorded nothing at all, which is why it had never been diagnosable.

## Where We Started

Two different ways a turn could stop and never come back.

**The first turn of a Journey.** Starting a brand-new Journey, the very first turn could fail to settle. The cause was inside the app, on both sides of one file: a fresh Pi session has no entries yet, so the app wrote a chapter manifest whose coordinates were `null`. The reader was built to reject `null` — correctly, because a coordinate that exists must be a real coordinate — and that rejection threw, which failed saving the projection, which failed the turn.

The reader was right. **The writer was wrong.** A value that does not exist should be absent, not present-and-empty.

**A `Finishing` that would not end.** You hit this directly: stuck in `Finishing`, no way to cancel, no way to send, and the only exit was restarting the app. The durable record shows the wait ran **43 minutes and 29 seconds**, against a typical settlement of about **5 seconds** and a worst case ever recorded of **42 seconds**.

And `Finishing` is displayed in exactly the state where the Cancel button is hidden — not by oversight, but because Cancel kills a running process and by then nothing is running. So the label and the one control that could have helped were mutually exclusive **by construction**, while sending stayed blocked.

## What Changed

### A turn survives a chapter file it cannot read

An unreadable chapter manifest no longer fails a turn. Publication is skipped, exactly as it always has been when there is no manifest at all, the reason is recorded, and **the turn settles**.

What the reader accepts is unchanged. It did not become more permissive; the consequence of its refusal became proportionate. And the writer no longer produces the file that caused this: a coordinate that does not exist is now simply absent.

One Journey on your machine has such a file on disk right now. It will now settle instead of failing.

### You can stop waiting

Once `Finishing` has run for more than a minute, a notice appears with how long it has been waiting and a **Stop waiting** button. Confirming it releases the composer so you can send a new message.

It is deliberately honest about what it does and does not do. It does not undo anything already saved — your message and the answer are stored and stay exactly as they are. It does not stop work that is still running. If the turn still owes Mirror an update, that is completed in the background by the recovery routine that already exists for this. And the turn is recorded as one that did not finish settling, so the delay is visible afterward rather than invisible.

**The control is withheld while work is genuinely executing.** That is the point of it rather than a limitation: if Pi really is still running, stopping the wait would either do nothing or require abandoning a process that is doing real work.

### The threshold

One minute. Chosen to sit past every settlement that has ever completed here — the longest was 42 seconds — so the control never appears in front of a turn that was simply going to finish.

## Conscious Exclusions

**This does not explain why a settlement hangs.** It makes the consequence survivable. The cause is still unknown, and the record it now writes is the thing most likely to eventually explain it.

**There is still no exit when Pi is genuinely occupied.** If a run is truly hung but its process is still alive, no control appears and the app says nothing about why. Refusing to act there is correct; being silent about refusing is not, and that gap is recorded as its own work rather than papered over.

**No timeout was added.** Nothing gives up on a settlement automatically. Only you can know that a wait has become futile, because a hung process and a working one look identical from the inside.

**The stale chapter file was not repaired.** It describes a session with zero entries, so there is nothing in it to lose. Rewriting it would have been a change with no beneficiary.

**Two Journeys that never produced a receipt are still unexplained.** Their chapter files read cleanly, so this release's fix is not their cause. Said plainly rather than folded into the fix it does not belong to.

## What We Learned

**Absent and empty are not the same thing, and the difference has to be decided once.** The writer and the reader each had a defensible rule and the rules disagreed. The fix was not to loosen the reader but to make the writer say *nothing* where there is nothing to say.

**A rejection's severity belongs to the caller, not to the checker.** The same unreadable file is fatal when you are rebuilding a chapter index and harmless when you are deciding whether to publish. One checker, with the caller choosing what the refusal costs.

**Two sets of rules written separately drift apart.** The writer is Rust, the reader is TypeScript, and they had quietly disagreed for weeks. They are now pinned together by a file the writer itself produces and the reader is required to accept — so if either side changes its mind alone, the build fails rather than production.

**A repair can be complete while the screen still says it is not.** The `Finishing` lockout came from a real earlier fix: the background repair routine was deliberately freed to act while a turn was finalizing. It did its job. But nothing told the interface, so everything could already be healthy while the composer stayed locked indefinitely. Fixing the state and fixing what is shown about the state are two jobs.

## Next Horizon

Why a settlement hangs at all — now, for the first time, with a record of it when it happens. Alongside that: telling the difference between a turn that settled quietly and one that was rescued, which still looks the same from the outside.
