# v0.4.0-alpha.3 - Timing the Start of a Turn

**Date:** 2026-11-04

## Highlights

- **No visible change.** This version measures; it does not yet make anything faster.
- **Every turn's start is timed.** From the moment the turn is admitted to the moment Pi starts its
  agent, each step is recorded in the Journey's timing ledger (CR194).
- **Still Intel only, and not signed.**

## Where We Started

After Send, Pi takes about 2 seconds to have the message on a small Journey and up to 42 seconds on
a long one. Measured apart on copies, Pi, the session and the Mirror context explain about 10 of
those seconds. The rest happens only in the running app.

## What Changed

- The Pi worker marks each step as it finishes: admission, session baseline, journal running,
  extensions, Mirror context, workspace, spawn, prompt write, first output and agent start. One
  `turn_start` record per turn goes into `settlement-timings`, also when the turn ends before the
  agent starts. A failed write never fails the turn (CR194).

## What Does Not Change

The same Mirror core and the same Pi as v0.4.0-alpha.2. Nothing in a home's database or in the
app's preferences changes.

## Conscious Exclusions

- **No fix yet.** The fix follows the measurement.
- **The timing ledger keeps 256 records per Journey**, so it now holds about half as many
  settlements as before.
- **No signing, notarization or Apple Silicon build** yet.

## What We Learned

In development, on a small session, the Mirror context already takes 6 of the 8 seconds, and every
native step together takes a tenth of a second. Measuring the running app is cheaper than guessing
from its parts.

## Next Horizon

Read the timings of long Conversations in production, then fix the step that grows (CR194).
