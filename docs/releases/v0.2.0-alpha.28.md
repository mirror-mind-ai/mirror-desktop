# v0.2.0-alpha.28 — Workspace Signals Stay Legible

**Date:** 2026-10-01

## Highlights

- Restores a usable window position and size before the Desktop window becomes visible.
- Makes model identity and its turn scope readable in the Composer instead of exposing raw provider notation.
- Gives Ready its own green completion signal and makes all six sidebar agent states distinct by shape.
- Keeps an interrupted or failed Journey legible after restart without inventing a new stored status.
- Preserves a coherent Agent Comment trail when a run settles or a later turn arrives.

## Where We Started

Daily work could reopen in the wrong place, model selection could be mistaken for current runtime,
and the compact Journey rail could not reliably distinguish inactive, active, terminal and failed
work. The latter failure was particularly acute for Journeys with custom images: the compact badge
could be positioned outside the rail and be clipped almost entirely.

The Conversation surface also fragmented a continuous sequence of Agent Comments into repeated cards
at run boundaries, making one working trail look like separate unrelated statements.

## What Changed

**Window restoration is native and reachable.** Desktop records ordinary moved and resized geometry,
applies usable dimensions before position at event-loop readiness, and falls back visibly when the
stored arrangement is malformed, implausible or no longer reaches any monitor work area. Rejected
evidence is retained rather than silently overwritten.

**The Composer names the actual choice.** Model identity distinguishes the model used for the current
turn from the selection that applies to the next turn, qualifying ambiguous names and keeping
thinking state only where it adds information.

**Sidebar activity has a readable grammar.** Idle, Working, Finishing, Ready, Interrupted and Failed
now have different glyph topology. Working and Finishing retain the selected Journey accent but clear
a measured 3:1 light-theme floor; interruption uses a contained neutral register and failure has its
own orange-red register. Interruption and failure read the latest durable turn-journal record and
therefore remain truthful through restart without a recognition ledger.

**The compact rail contains its badge.** The expanded card grid had named areas that became implicit
columns outside the rail's sole icon cell. Compact card copy is now hidden and the status badge is
released from the card grid, returning it to the tile corner. Measured horizontal overflow falls from
77px scroll width to the 55px rail width; a custom-image badge that previously lost 17 of its 19
pixels is fully visible.

**Agent Comments stay a trail.** Adjacent comment material remains one coherent run-scoped surface as
live work settles and subsequent turns arrive, without merging the underlying transcript content.

## Conscious Exclusions

- No release tag, push, publication, updater endpoint mutation, signing claim or notarization is made by this preparation.
- Ready remains a transient five-second arrival signal; only interruption and failure survive restart.
- Sidebar interruption and failure remain per Journey, not per Conversation, and do not create an acknowledgement ledger.
- Window restoration does not persist fullscreen, minimized state, monitor fingerprints or workspace content.

## What We Learned

A compact layout is not simply an expanded card at a narrower width: named grid areas that have no
matching rail cells can create invisible layout authority outside the rail. Visual confirmation was
not enough; measuring the actual clip and boxes identified why a working badge disappeared.

The same discipline applies to status meaning. Colour and animation make poor sole carriers at rail
size and under reduced motion. Shape must state the difference, while durable evidence must be read
from the structure that actually owns it rather than inferred from agent prose.
