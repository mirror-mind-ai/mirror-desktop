# v0.2.0-alpha.4 — Semantic Conversation Surface

**Date:** 2026-09-11

## Highlights

- Keeps an exact ready Journey conversation mounted while same-Journey authority refreshes, eliminating settlement flicker.
- Composes assistant turns as Agent Actions, System Surfaces, and Agent Comments by semantic authorship rather than runtime chronology.
- Groups exposed action summaries with their tools while preserving honest fallback actions for unclaimed operations.
- Keeps preparing and running actions visible, collapses settled detail, and makes historical turn anatomy recoverable on demand.
- Retains only terminal action evidence in the channel-local conversation projection under exact Journey and turn authority.
- Adds one accessible copy control to every fenced Markdown block in Agent Comments, with exact raw-content copying and truthful feedback.

## Where We Started

The alpha conversation surface exposed useful runtime activity, canonical Mirror and Ariad surfaces, and final responses, but presented them too much like one chronological process log. A same-Journey authority refresh could temporarily replace an already ready response with a loading surface. Completed operations remained visually prominent, older turns had no semantic compaction model, and restarting the app discarded terminal tool detail that users had already seen.

Highlighted content had a related inconsistency. Whole messages and selected quoted drafts could be copied, while equivalent fenced commands, configurations, plain text, and wireframes inside Agent Comments required manual selection.

## What Changed

Mirror Desktop now preserves the exact ready conversation during a same-Journey authority refresh and reclassifies it only when authoritative state requires a real transition. Assistant content is rendered through one semantic turn projection: Agent Actions contain exposed operational intent and tools, System Surfaces retain canonical Mirror or Ariad authorship, and Agent Comments contain the consolidated response.

An exposed summary owns subsequent operations until the next summary. Operations without such a summary receive a truthful fallback label derived from their existing tool name and argument preview. Preparing and running actions and tools are forced open; settlement returns them to collapsed manual control. The active and newest completed turns retain full anatomy, while older turns prioritize comments behind one counted disclosure.

Terminal summaries, sanitized tool output, arguments, source order, and terminal statuses can now survive restart in the channel-local conversation projection. Restore requires exact Journey, generation, run, turn, reconciliation, and assistant-message authority. Running state and manual disclosure choices are never persisted, and legacy conversation schemas remain readable.

Finally, fenced Markdown blocks in Agent Comments use their existing semantic code-block representation to offer a dedicated copy control. The control copies only the parsed block body—not fences, language declarations, rendered links, decoration, or neighboring prose—and reuses the existing keyboard-accessible clipboard feedback boundary.

## Conscious Exclusions

- Apple Developer ID signing and notarization remain unavailable and are not claimed by this alpha.
- Updater artifact signing does not imply Apple application signing or notarization.
- Copy controls are not broadened by visual similarity into System Surfaces, tool arguments or outputs, artifacts, Journey documentation, user messages, or inline code.
- Hidden model reasoning is neither requested nor reconstructed; only already exposed summaries and terminal evidence are retained.
- No stable or production updater channel is introduced; this remains the governed `0.2.0` alpha line.
- Application updates do not mutate Mirror homes, `memory.db`, identity, credentials, Journey content, conversations, app data, or Nautilus Harness state.

## What We Learned

Conversation clarity depends on preserving authorship and proximity, not merely reducing detail. Operational evidence is useful while work is active and when a user deliberately inspects history, but it should not dominate the settled dialogue. Runtime authority should keep running work visible, while exact terminal evidence—not stale UI state—supports later inspection.

Copyability follows the same principle. A semantic rendered block is a reliable product boundary; command-like words and dark backgrounds are not. Reusing one clipboard boundary keeps feedback and accessibility consistent without spreading native authority through unrelated renderers.

Continue alpha observation before deciding whether System Surfaces or tool output need separately refined copy contracts. Apple signing and notarization remain a separate capability track.
