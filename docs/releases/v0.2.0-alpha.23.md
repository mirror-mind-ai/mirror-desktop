# v0.2.0-alpha.23 — Journey Rail and Agent Status

**Date:** 2026-09-27

## Highlights

- Polishes the collapsed sidebar into a compact Journey rail.
- Prevents Conversation lists from rendering as vertical text inside the 72px rail.
- Harmonizes custom Journey images, default glyphs and the app icon in compact mode.
- Replaces the old pin-button/runtime overload with a dedicated Journey agent-status indicator.
- Shows `Idle`, `Working`, `Finishing` and `Ready` in the sidebar and beside the active Journey name.
- Moves Pin/Unpin to the exact-Journey context menu while keeping it available during active runs.
- Keeps runtime semantics unchanged: admission, cancellation, finalization and synchronization are untouched.

## Where We Started

Two pieces of the interface were trying to do too much.

The collapsed sidebar worked functionally, but it still behaved like the full
sidebar had been squeezed into a narrow column. When a Journey's Conversation
list was expanded, the `CONVERSATIONS` heading and entry titles wrapped into a
vertical strip. Journey icons also carried nested card treatments that made the
rail feel improvised rather than intentional.

At the same time, the visible pin control was carrying two meanings. It was the
place where pinning lived, but it was also visually adjacent to runtime state.
That made it too easy to read pinning, activity and selection as one overloaded
signal.

## What Changed

**The collapsed sidebar is now a rail.** Compact mode hides the focused
Conversation list and its toggle instead of trying to squeeze a second-level
navigation surface into 72px. This is presentation only: compacting does not
close the selected Conversation, and expanding restores the same context.

Compact Journey tiles now have their own grammar. Default and system Journey
marks are glyphs, custom images keep their image frame, and the selected state
for custom images hugs the image rather than leaving a larger rectangle around
it. The app icon at the top of the rail uses the same visual module as custom
Journey images, so the rail reads as one family of marks.

**Agent state has one visible source.** `JourneyAgentStatusIndicator` replaces
the old pin-button/runtime mix. The same component appears on each Journey row
and beside the active Journey name in the header. It reports four states:
`Idle`, `Working`, `Finishing` and `Ready`. Working pulses, Finishing breathes
more slowly, Ready is static, and reduced-motion keeps the state without the
motion.

Ready is intentionally session-local attention, not a new durable notification
ledger. If a turn completes while its Journey is open, Ready stays for five
seconds and then returns to Idle. If it completes in the background, Ready
persists until that Journey is opened; once acknowledged, the same five-second
window begins. In expanded Recent cards, the human state label temporarily
replaces the last-worked timestamp; the timestamp returns when the Journey goes
back to Idle.

**Pinning moved to the Journey context menu.** The menu now begins with a
checked Pin/Unpin item. Because pinning is a local preference rather than a
Journey mutation, it remains available while agents are running. Edit, create,
move and delete still remain disabled during runtime.

## Conscious Exclusions

- No change to process admission, cancellation, finalization, synchronization or Mirror append semantics.
- No durable unread-completion ledger across app restarts.
- No click action on the status indicator; selecting a Journey still belongs to the Journey item.
- No redesign of Journey ordering or the full expanded sidebar model.
- No expansion of Conversation navigation inside the compact rail.

## What We Learned

The rail problem was not the Conversation list alone. Removing that list fixed
the broken vertical text, but the interface still felt wrong while default
Journey glyphs rendered as small cards inside larger cards. A compact surface
needs its own grammar; it cannot simply inherit a full-card grammar at smaller
scale.

The same lesson applied to agent state. Adding animation to an existing pin
button would have preserved the overload. The cleaner move was to separate
meanings: pinning becomes a contextual preference, and agent state becomes a
status language shared by the sidebar and header.

The final adjustment came from looking where the Navigator was already reading:
the last-worked timestamp. While a Journey is active, that line is less useful
than knowing what the agent is doing. Reusing the line for Working, Finishing
and Ready made the state legible without adding another row.

## Validation

Both CRs were validated on the Dev channel before merge. The Navigator confirmed
that the compact rail no longer shows broken Conversation text, that icon and
tile sizing now harmonize, that pinning works from the context menu, and that
agent state reads correctly in the sidebar and header through Idle, Working,
Finishing and Ready.

Automated coverage now pins the compact rail contract, the shared status
component, the five-second Ready attention window, background completion
acknowledgement, contextual Pin/Unpin during runtime, reduced motion and light
theme behavior.
