# v0.2.0-alpha.54 — Columns That Wrap, and a Canvas That Uses Its Width

**Date:** 2026-10-18

## Highlights

- **A table cell wraps inside its own column instead of being drawn over the next one.** The Canvas progress bars and their counts were being covered by the text beside them.
- **Both markdown table renderers are repaired, not just the one that was reported.** The same declarations served the Canvas, the documentation browser and tables inside chat messages.
- **A progress bar is never broken across two lines,** because a broken bar reads as two bars and a branch name broken mid-token reads as two names.
- **The Canvas uses the whole panel.** It was capped at a reading measure written to keep paragraphs from running too wide — and the Canvas has no paragraphs.
- **Nothing is hidden to achieve any of this.** No ellipsis, and no table that can overflow its panel.

## Where We Started

The Canvas was redrawn in the previous release to show only open work. The Navigator then sent a
screenshot of it with one instruction: fix the column that is truncating its content.

It was not truncating. The text of the `Estado` column ran past its own cell and was painted *on top
of* the `Progresso` column, so two columns occupied the same pixels and the progress bars underneath
were unreadable. Nothing was cut off with an ellipsis; something was drawn over.

The cause was one pair of declarations: a `max-width` cap together with `white-space: nowrap` and no
overflow rule. A cell that may not grow past the cap and may not wrap cannot shrink either, so it
renders outside itself onto whatever is there. That makes it a rendering defect rather than a content
one — no cell length makes it correct, because the collision fires for any cell wider than the cap.
A shorter cell only postpones it.

With the collision gone, the next thing was visible: the tables sat in the left two thirds of the
panel with the right side empty.

## What Changed

### Cells wrap, and the cap stays

Both cell rules keep their cap and gain `overflow-wrap: break-word` with `white-space: normal`. The
cap is what keeps a column readable; the wrapping is what keeps it honest, and `break-word` covers
the one case wrapping alone does not — a single token longer than the cap. Cells also align to the
top, so a row whose tallest cell now wraps to three lines does not centre its one-word neighbours
against it.

A new rule per renderer keeps code spans intact. They wrap only if a single token genuinely cannot
fit, so a ten-block progress bar is never split and a branch name is never broken in the middle.

### The same defect in the second renderer

`ArtifactMarkdown` draws the Canvas and the documentation browser; a separate rule draws tables
inside chat messages. Both carried identical declarations, so the collision was reachable from three
surfaces and was reported from one. The second occurrence was found by searching for the
declarations, not assumed from the first.

### The Canvas is no longer held to a prose measure

The Canvas view carried `max-width: 54rem`. That is a *reading measure* — it exists so a paragraph
does not run to a two-thousand-pixel line. The Canvas has no paragraphs **by its own instructions**,
which say that a paragraph in it is a defect. The measure was constraining the one kind of content it
was never written for, and the tables were already filling one hundred percent — of 864 pixels.

The measure is gone. Canvas tables are now exactly the width of the panel and the per-cell cap is
lifted inside the Canvas so the columns distribute across it. Lifting that cap does not undo the
first repair: the cap existed to stop a table growing without bound, and a table pinned to its
container's width cannot overflow at all. The mechanism was replaced by a stronger one rather than
removed, and the collision stays fixed for its own reason, which is that the cells wrap.

### Two alternatives rejected on the record

`text-overflow: ellipsis` would stop the collision by *hiding* content, which answers a complaint
about losing content with the thing complained about. Removing the cap entirely would stop it by
letting the table grow without bound. A guard asserts the cap is still present in the shared rule, so
this repair cannot quietly become that one.

## Conscious Exclusions

- **The Canvas cell *content* was not shortened.** Those cells also break their own instruction that a cell is a short state fact and not a sentence. Shortening them is an editorial act on what the Navigator reads, so it is recorded as a decision rather than performed. With this release the long cells wrap and stay legible, which makes the two questions genuinely separate.
- **The chat-message renderer keeps its horizontal scroll** for tables wider than the message column, and the documentation browser is untouched. The width change is scoped to the Canvas on purpose, because a documentation table may genuinely need more room than the panel.
- **No visual verification yet.** A stylesheet is compiled into the bundle, and the Navigator has seen only the defect. The Dev build cannot show it, because the Dev identifier does not read the production Journeys and therefore cannot render this Canvas. This release is what makes the check possible.

## What We Learned

**A constraint written for one kind of content can be silently wrong for another.** The reading
measure was correct for prose and had never been reconsidered for a surface that contains no prose by
rule. It was not a bug in anything; it was a right answer to a question nobody re-asked.

**A guard that matches a substring answers for the file's ordering rather than for the rule.** The
new selector for Canvas tables *contains* the shared selector as a substring. The existing guard
passed only because the shared rule happens to appear first in the stylesheet. It now anchors on a
line start and asserts the rule is declared exactly once.

**An absence assert must strip comments before it can mean anything.** The check that the reading
measure was gone failed — on the comment written to explain its removal. The repair was correct and
the instrument was not, which is the third time in this stretch that a verification of mine counted
the wrong thing and aborted before writing. That it aborts before writing is the reason the practice
of building the whole plan and asserting every anchor first keeps earning its cost.

**A symptom reported in good faith can name the wrong mechanism.** Reported as truncation, it was
collision — and the difference decides the repair, because the fix for truncation is to show less and
the fix for collision is to lay out properly.

## Next Horizon

The visual check closes this work: the `Estado` column should wrap inside its own column with
`Progresso` legible beside it, and the tables should reach the right edge of the panel. Until that is
seen, the change request stays open — every other claim here is proved by a guard, and this one is not.

Then the separate question this release deliberately left alone: whether the Canvas cells get
shortened to the short state facts their own instructions ask for.

The field falsifier from the previous release is still open. No turn has yet frozen at *Finishing* on
it, so the exits unified there remain unexercised in the field, and a minute frozen with nothing drawn
would be a refutation rather than a pending item.
