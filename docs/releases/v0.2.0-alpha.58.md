# v0.2.0-alpha.58 — Your Mirror, Found

**Date:** 2026-10-27

## Highlights

- **Opening Mirror Desktop for the first time no longer starts with a form.** Your Mirror is found and you connect with one click.
- **Each requirement is checked and explained:** Mirror itself, a supported version, your Mirror home and its memory, uv, and Pi with Node. Anything missing says what to do.
- **The right Mirror, not a guess.** When one Mac holds several Mirror homes, the one proposed is exactly the one your Mirror installation names.
- **Your keys stay where they are.** Only the settings that say whose Mirror this is are read; an OpenRouter key is noted as present or absent, never read.
- **The form is still there.** *Use a different Mirror…* opens it, and Settings gains *Find my Mirror* to fill it automatically.

## Where We Started

Mirror Desktop assumed Mirror was already installed, and then asked the person to prove it by hand.

Its first screen wanted an absolute path to the Mirror installation, another to the personal Mirror
home, and a lowercase user name. People who use Mirror every day rarely know those by heart. The app
did try to find them, but only from settings exported in a terminal, which an app opened from the Dock
or Finder never sees, so for the ordinary first launch it found nothing.

This is the first step of a larger change. Work on small fixes has been paused so that arriving at
Mirror Desktop gets easier, starting with people who already use Mirror.

## What Changed

The first screen now looks for your Mirror in the usual places (your home folder's `mirror`,
`Code/mirror` and a few others), or in a folder you choose.

Once it finds one, it reads Mirror's own configuration to learn whose Mirror it is, following the same
rule Mirror itself follows. It reads only the handful of settings that name your Mirror home; every
other line, including any keys, is skipped as it is read.

It then lists what it checked, each with a plain sentence. When everything is in place, **Connect**
saves the connection through the same validation as before, and your Journeys load as they always
have. When something is missing, the screen names it and says how to fix it, and **Check again**
looks once more.

Setups this screen cannot represent faithfully, such as a Mirror configured to keep its database
somewhere else, are not guessed at: the screen says so and offers the form.

Measured on the development Mac, discovery chose the right Mirror among seven homes and proposed a
connection identical to the one that had been typed in by hand.

## Conscious Exclusions

- **Nothing is installed yet.** If Mirror, uv or Pi is missing, the screen tells you how to get it; installing it for you is the next step.
- **Whether your AI provider is signed in is not checked here.** Pi offers no way to list providers without guessing, so that check belongs to the step where you choose one.
- **Mirror itself was not changed.** This release works with the Mirror you already have.
- **A missing OpenRouter key is shown but does not block connecting**, because conversations work without it.

## What We Learned

**The quickest way to find something is to ask whoever already knows.** Mirror already knows whose
Mirror an installation belongs to; it says so in its own configuration. Reading that, with Mirror's
own rule, was enough. No change to Mirror was needed, and none was made.

**A test that passes before the code exists may be testing nothing.** The check that no key leaks into
what the screen receives passed against an empty placeholder. It only became evidence when the code
was deliberately broken to leak a key, and the check caught it.

## Next Horizon

The last check for this step happens on a clean macOS account: install Mirror there by its own guide,
install this release, and connect with one click. When that passes, the paused small fixes resume.

After that, the assistant goes further: installing what is missing, creating a Mirror for someone who
has none, and connecting AI providers together with them.
