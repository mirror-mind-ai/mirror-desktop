# v0.2.0-alpha.18 — Local Voice Composition

**Date:** 2026-09-24

## Highlights

- Adds an optional microphone control beside the Composer for recording a spoken prompt.
- Installs a managed local `whisper.cpp` component only after explicit consent.
- Downloads the transcription engine and model from the Mirror-controlled update endpoint with SHA-256 verification.
- Keeps audio local: recordings are converted, transcribed and deleted on this computer.
- Appends the transcript into the draft that was active when recording started; it never sends automatically.
- Lets the user choose the speech model and spoken language in Settings → Voice.
- Improves Portuguese recognition with band-limited audio resampling and `small-q5_1` as the recommended model.
- Fixes the light-theme voice controls, status badges and hover contrast introduced during validation.

## Where We Started

The Composer was text-only. If the Navigator wanted to speak a prompt, the
only honest paths were external dictation or an out-of-band transcription tool.
That would have made the Desktop depend on operating-system behavior or a
network service outside the product's consent and authority model.

Voice input also carried a boundary risk. A microphone button can look like an
agent command, and a speech-to-text feature can quietly become a remote service
or an automatic Send gesture if the product does not separate those decisions.
For Mirror Desktop that would be wrong: transcription is input composition, not
an agent turn.

## What Changed

Mirror Desktop now owns a local voice-composition boundary. The app can install
a pinned `whisper.cpp` executable and a selected model under the channel-local
app-data directory. The component manifest is fetched from the Mirror update
endpoint, all downloads are size- and SHA-256-verified, and the component can be
removed from Settings.

Installation and microphone capture are separate consents. Installing the local
component never starts recording. Recording starts only from the microphone
control, and the resulting audio is converted in the app to bounded 16 kHz mono
PCM16 WAV before crossing the native boundary. Native code receives bytes, not
paths or command-line arguments, writes one temporary WAV, runs the pinned
executable with fixed arguments, and deletes the temporary file on every path.

The destination is captured when recording starts. If the user navigates while
transcription is running, the transcript still lands in the original draft and
the user is told where it went. Existing text is preserved; the transcript is
appended as editable Composer text; Send remains manual.

Portuguese quality drove a second pass. Plain interpolation from 48 kHz capture
to 16 kHz folded high-frequency content back into the speech band and hurt
recognition. The app now uses band-limited sinc resampling. The original small
`base` model remains available as a lightweight option, but `small-q5_1` is the
recommended default because it is the smallest tested model that handled
Portuguese and English dictation acceptably on the validation machine.

A spoken-language preference is also available. Automatic detection remains the
safe default, but choosing Portuguese, English or another offered language skips
the detection pass and noticeably reduces wait time when the user knows what
they are about to speak.

## Conscious Exclusions

- Voice transcription does not send the prompt, start Pi, invoke Mirror Core or create an agent response.
- No audio is uploaded, persisted as history, attached to the conversation or retained after transcription.
- No streaming or partial transcript UI is included; transcription returns one final text result.
- No voice commands, translation, diarization, wake word, push-to-talk global shortcut or Send-by-voice is included.
- The initial published component endpoint includes macOS x64 only. Apple Silicon `aarch64` with Metal remains future work.
- `large-v3-turbo` was characterized but is not published as an offered model in this release.

## What We Learned

The hard part was not drawing a microphone. It was keeping authority narrow.
The useful version of this feature is the one that behaves like typing: it
helps compose text and then stops. Everything after that remains the same
explicit Composer contract the Desktop already had.

The validation also showed that audio preparation is part of transcription
quality, not plumbing. A small model can only work with the signal it receives.
Once resampling stopped corrupting the speech band, the remaining trade-off was
honest: faster models are less accurate, larger models wait longer, and the
Navigator should be allowed to choose.

## Next Horizon

Publish a macOS Apple Silicon build of the voice component with Metal enabled,
then revisit model recommendations on that faster hardware. If daily use shows
language selection becoming repetitive, the next refinement is a small per-user
language default that stays visible and easy to change rather than inferred from
locale.
