# v0.4.0-alpha.4 - Managing Journeys From the Tree

**Date:** 2026-11-06

## Highlights

- **A quieter tree.** Completed, paused and planned Journeys stay out of the tree until "Show N
  inactive" brings them back, and the whole tree collapses or expands at once (CR199, CR200).
- **You can see where the agent works.** Under a Journey's name, "Working in ~/…" names its folder,
  opens it in Finder, and turns amber when the folder is gone (CR201, CR202, CR197).
- **Drag a Journey to move it.** Into another Journey, above or below one, or to the top of the
  tree, with a sentence that says what the drop will do (CR203).
- **Delete a Journey with its records.** The confirmation lists what will go from Mirror, what other
  Journeys keep, and what Nautilus moves aside; a backup is taken first (CR204).
- **Still Intel only, and not signed.**

## Where We Started

The tree only displayed Journeys. Creating, moving and deleting them was done elsewhere, or not at
all: Mirror deleted only an empty Journey, a running turn anywhere disabled every edit, and a Journey
whose folder had moved sent its turn to the neutral folder without a word.

## What Changed

- **Reading the tree.** Inactive Journeys are hidden by default, still found by search, and an
  inactive Journey that holds an active one stays, dimmed. Collapse all keeps the path to the
  selected Journey. Both choices survive a restart. Hovering a Journey shows its folder (CR199,
  CR200, CR201).
- **Where the agent works.** The app asks Mirror for the Journey's folder before every turn instead
  of trusting what it read at start, so a path set from the terminal applies at once, and a folder
  that no longer exists is said, not silently replaced (CR202, CR197).
- **Editing while an agent works.** A turn running in one Journey no longer blocks creating,
  renaming, moving or repainting the others, or the running one itself. Only deleting a Journey that
  is working, or one above it, is refused, with the reason (CR099).
- **Moving by dragging.** The drag runs on pointer events, because the browser's drag never started
  in the app's web view. A drop onto a Journey's own child is refused, a drop where it already is
  sends nothing, and the line under the tree waits for Mirror's answer (CR203, CR098).
- **Deleting.** Mirror deletes the Journey and every record that belongs to it in one step, behind a
  backup it verifies first; other Journeys' records that only pointed at it keep their content.
  Nautilus moves its own files for that Journey aside, into `deleted-journeys/`. Deleting the project
  folder too is a separate box, off by default, and refused for a home folder, a folder holding
  Nautilus's or Mirror's data, or one holding another Journey's folder. A Journey with child Journeys
  cannot be deleted (CR204).

## What Does Not Change

Nothing in a home's database schema changes, and no migration runs. The Mirror core moves from
0.39.0 to `mirror-mind@0.40.0-next.1`, a preview published for Nautilus: it adds the Journey
deletion calls, and the terminal's `mirror` keeps working on the same home. Pi is the same.

## Conscious Exclusions

- **No cascade.** A Journey with children is refused; move or delete the children first.
- **The deleted project folder is not moved to the Trash.** The confirmation says so.
- **No signing, notarization or Apple Silicon build** yet.

## What We Learned

Deleting by reach would have erased other Journeys' history: in a long-lived home almost a thousand
memories sit under a Journey other than their conversation's. Deleting by ownership, and showing the
list before acting, made the irreversible act legible.
