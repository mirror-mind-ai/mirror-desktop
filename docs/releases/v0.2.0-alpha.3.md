# v0.2.0-alpha.3 — Alpha Feedback and Operational Reliability

**Date:** 2026-09-10

## Highlights

- Preserves user-authored Shift+Enter line breaks in conversation messages.
- Makes context usage timely and authoritative for the exact active Pi session and model.
- Settles provider failures instead of leaving turns permanently at `Working…`.
- Keeps successful completion quiet through one `Working…` → `Finishing…` lifecycle.
- Loads Artifact folders lazily, adds workspace reload, and makes `src-tauri/target/release/bundle/` reachable without traversing all Cargo output.
- Restores readable first-message suggestion labels across Daylight, Mist, and Parchment.
- Separates updater-free Dev builds from trusted, updater-configured user builds.
- Simplifies the Journey sidebar around the Mirror Desktop title, version, and icon.

## Where We Started

The public alpha and trusted self-update path were already operational, but daily use exposed smaller failures that accumulated into friction. Authored line breaks disappeared, context percentages arrived late or not at all, provider errors could strand the composer, routine completion became visually noisy, generated release bundles were difficult to reach, and parts of the light-theme and sidebar hierarchy remained unclear.

The development and user build routes also needed an explicit trust contract. A Dev bundle must remain independent from updater configuration, while a user-identity build must never initialize an updater without its governed endpoint, public key, and signing boundary.

## What Changed

Mirror Desktop now preserves paragraph line breaks only for user messages, leaving assistant Markdown behavior unchanged. Context usage accepts live events immediately and recovers only from the exact active Pi session file, generation, ancestry branch, provider, and model. A process exit is no longer treated as successful without complete Pi execution evidence, so provider failures durably terminalize and return control to the composer.

Routine turn completion now remains under `Finishing…` until the Mirror conversation append and acknowledgement settle, then becomes silent. Repair UI appears only when durable work remains after finalization.

The Artifacts workspace now loads one bounded Journey directory at a time. Manual reload preserves valid expansion and selection state, rejects stale responses, and keeps the last successful tree visible on localized failures. Cargo `target` is navigable while high-volume intermediates remain hidden, allowing release bundles to be revealed safely without an eager scan of the complete build tree.

The isolated Dev bundle no longer initializes the updater plugin. Generic user-channel routes now overlay the governed alpha updater configuration, and user builds fail closed unless trusted signing material is available. Unsigned local validation remains exclusive to the Dev identity.

Finally, light-theme suggestion buttons use semantic contrast tokens, and the sidebar header now top-aligns the app icon with a compact title/version group. Redundant `DEV LAB` and `Journey Navigation` labels were removed from that header while the icon badge and assistive development-channel identity remain intact.

## Conscious Exclusions

- Apple notarization is still not claimed until Developer ID and notarytool credentials exist.
- Preparing these notes and version files does not authorize signing, tagging, pushing, publishing, endpoint mutation, GitHub Release creation, or installation promotion.
- No stable or production updater channel is introduced; this remains the `0.2.0` alpha line.
- Self-update remains limited to application bytes. Mirror homes, `memory.db`, identity, credentials, Journey content, conversations, app data, and Nautilus Harness state remain outside its mutation boundary.

## What We Learned

Alpha reliability is shaped as much by truthful settlement and quiet transitions as by headline features. A percentage must identify the exact session it describes; a successful process must provide completion evidence; and finalization should remain visible only while meaningful durable work is still happening.

Generated artifacts are legitimate operational content, but exposing them safely requires lazy traversal rather than a blanket exclusion or an unbounded scan. Development isolation and updater trust follow the same principle: each route should state exactly which authority it carries and fail closed when that authority is absent.

## Next Horizon

Run the clean release gates for `v0.2.0-alpha.3`, produce the signed alpha artifacts, inspect provenance and checksums, and rehearse the installed-app update from `v0.2.0-alpha.2` before any authorized publication. Notarization remains a separate capability boundary.
