# v0.2.0-alpha.5 — Release Clarity and Pre-Release Polish

**Date:** 2026-09-13

## Highlights

- Shows an authoritative summary and complete release notes for the exact offered version before update consent.
- Recognizes the installed release after exact-version relaunch, preserves release-note access after acknowledgement, and keeps update availability visibly persistent.
- Separates compound Agent Action summaries, clears tool ownership at empty boundaries, and preserves ordinary multiparagraph narrative grouping.
- Automatically clears point-in-time composer errors and notices after eight seconds while keeping actionable conditions visible.
- Restores readable Journey search, sidebar collapse, and pending attachment controls in Daylight, Mist, and Parchment.
- Adds deterministic release-reading metadata, body digest validation, channel-local acknowledgement state, and roadmap consistency checks.

## Where We Started

The alpha updater could identify and install a signed release, but release meaning remained peripheral. The notification carried version and preservation context while complete notes lived at an external coordinate. After relaunch, the application had no exact, durable way to explain what had just changed or let the user revisit those notes.

Conversation action grouping also retained one boundary ambiguity. A compound standalone summary could claim tools too broadly, while an empty summary could leave prior ownership active. Point-in-time errors rendered above the composer could remain indefinitely, forcing an app restart to clear stale feedback. Finally, Journey search and pending attachment controls still inherited pale dark-theme foregrounds on light surfaces.

## What Changed

Release staging now derives one bounded `release_reading` envelope directly from the canonical versioned release-note file. It carries exact product and version identity, title, digest, highlights, complete Markdown, canonical HTTPS URL, and a SHA-256 of the body. Mirror Desktop verifies that envelope before presentation. Historical updater manifests remain compatible and produce an honest unavailable-details state rather than generated or mismatched content.

Before update consent, the version popover presents concise highlights and Settings exposes the complete reading. Immediately before installation, the validated public reading is stored in channel-local application data. Startup promotes it only when the running application version exactly matches the pending target. An accessible sparkle marks unread release notes without adding status text to the compact chip. `Got it` removes only unread emphasis; the chip and Settings retain release-note access. `Later` closes an available-update popover without hiding the persistent update indicator.

Agent Action projection now splits strictly standalone compound emphasized summaries into independent action boundaries. Empty summaries terminate previous tool ownership, while normal multiparagraph narrative remains intact. This keeps tools attached to the action that actually authored them without turning prose into artificial operations.

Composer-end feedback now has an explicit presentation lifecycle. File-reference errors, attachment failures, terminal send warnings, and successful recovery information expire after eight seconds. Replacement cancels the old timer, stale callbacks cannot erase newer feedback, repeated warnings receive exact Journey and run keys, and Journey switching clears local transient presentation. Runtime binding, Agent Settings, blocked recovery, occupancy, retained lease, and Mirror synchronization notices remain condition-driven and persistent.

Light-theme interaction overrides now use semantic text, muted, accent, surface, and border tokens after the shared cascade. Active Journey search, result summary, clear action, sidebar collapse, pending attachment title, path, size, and file actions are readable across Daylight, Mist, and Parchment with measured enabled-text contrast of at least 4.5:1.

## Conscious Exclusions

- Conversation Spaces remains a planned product horizon; steering, expanded concurrency, persona spaces, multiple Journey conversations, and voice composition are not implemented here.
- Apple Developer ID signing and notarization remain unavailable and are not claimed by this alpha.
- Updater artifact signing does not imply Apple application signing or notarization.
- Historical updater manifests are not rewritten, and invalid What's New content never becomes installation authority.
- The only new application-data coordinate is bounded `whats-new-state.v1.json`; Mirror homes, `memory.db`, identity, credentials, Journeys, conversations, attachments, and unrelated app data remain outside updater mutation.
- Transient visual dismissal does not cancel, retry, acknowledge, or clear underlying operational state.
- No stable updater channel or automatic release promotion is introduced.

## What We Learned

Release trust and release understanding belong together but must remain separate authorities. The updater decides whether application bytes may be installed; the release reading explains those exact bytes. Binding both to one version coordinate gives the user useful context without letting presentation metadata weaken signature, consent, quiescence, or rollback.

Small persistent interface defects also accumulate operational weight. An action boundary that owns one tool too many, an expired error that never leaves, or a pale control on a light surface each makes the desktop feel less trustworthy. Precise semantic ownership, bounded temporal behavior, and measured contrast are complementary forms of product reliability.

## Next Horizon

Publish and verify the signed `v0.2.0-alpha.5` artifacts and updater manifests, then rehearse an installed-app update from `v0.2.0-alpha.4` to confirm exact pre-update reading, signed installation, relaunch recognition, acknowledgement, and preservation boundaries. Conversation Spaces remains the next planned capability horizon after alpha observation.
