# v0.2.0-alpha.24 — Compaction Chapters

**Date:** 2026-09-28

## Highlights

- Turns Pi compaction boundaries into readable Conversation chapters.
- Names chapter dividers from the compaction summary's own goal instead of inventing a separate title layer.
- Adds a chapter index panel with chronological chapters and a Most recent shortcut section for long indexes.
- Adds a manual Context compaction action from the context footer/menu.
- Keeps compaction mutually exclusive with active Journey work while leaving model selection available for the next turn.
- Shows manual compaction through the same live runtime component used for automatic compaction.
- Raises a compacting Journey in the Recent list, marks it Working, and announces successful completion with the Ready attention badge.
- Repairs manual compaction's Segment republication path so only the moved frontier is republished.

## Where We Started

Compaction made the agent's context sustainable, but it did not make the
Navigator's reading sustainable. Months of work still appeared as one long
Conversation. When Pi compacted the session, the model received a summary and
continued from it, but the Desktop did not show where that chapter ended, what
it was about, or how to navigate back to that point.

The problem became sharper when a large Conversation fit one model but not
another. Switching to a smaller context model could make the next send fail with
an input-too-large provider error, while the Desktop offered no manual way to
compact before sending. The only mechanism that could make room existed behind
the scenes.

## What Changed

**Compactions now create chapters in the reading surface.** The Desktop reads
Pi's own compaction entries, derives the exact closed segments and renders
chapter dividers in the transcript. These chapters are views over Pi evidence,
not new durable Conversation entities. The title comes from the summary's
`Goal`, and counts or dates are shown only when the underlying evidence can say
them honestly.

**The chapter index gives long Conversations structure.** The index opens as a
single chronological table of contents for short Conversations. Once the index
reaches seven chapters, a labelled Most recent section appears above the full
chronological list, carrying the current chapter and the two before it. Both
sections share one scroll region, and stable chapter numbers are reused in both
places so chapter 27 remains chapter 27 everywhere.

**Manual compaction is now a first-class operation.** The context footer/menu can
start a Context compaction while the Journey is idle. It is mutually exclusive
with turns, resets, Conversation switching and other operations that would move
the same generation. It is not a turn: no journal entry or run correlation is
fabricated. The same live runtime surface reports progress, success and failure,
so there is only one way for the UI to describe compaction.

**Compaction is visible as agent activity.** Although manual compaction is not a
turn, it is still the agent working. Starting it raises the Journey in the Recent
list and marks the Journey status as Working. Successful completion dispatches
the same attention lifecycle as a successful turn, so a background compaction
leaves a Ready badge waiting until the Navigator opens that Journey. Failures do
not masquerade as Ready; they remain on the compaction card inside the Journey.

## Conscious Exclusions

- No summary is sent to Mirror; compaction summaries remain Pi/session evidence.
- No durable chapter entity or separate chapter database is introduced.
- No read-only single-chapter mode is shipped yet; the index moves the existing transcript reading.
- No timeout is added to the one-shot manual compaction process in this release.
- No warning is added yet for switching to a model whose context window cannot hold the current Conversation.
- No provider-failure extraction from oversized-context JSONL errors is added in this release.

## What We Learned

The structure did not need to be invented. Pi was already writing the chapter
material: boundaries, retained-tail IDs, token counts and a summary with a clear
Goal. The Desktop's job was to project that structure without taking authority
away from the transcript.

The most subtle bugs came from treating compaction as either invisible plumbing
or as a normal turn. It is neither. It has to block the work that would mutate
the same generation, but it must not fabricate a run. It has to show progress
and attention, but only for the Journey that owns the process. That distinction
now lives in the UI: compaction is work, not a turn.

Manual compaction also exposed an important persistence boundary. Republishing
all Segment projections after a fresh Pi read can produce byte differences in
old, already-durable Segments. The correct repair is to publish only the frontier
that actually moved.

## Validation

The Navigator validated the Compaction Chapters surface in the Eval bundle.
Manual compaction now keeps the window responsive, reports progress only in the
owning Journey, raises that Journey in the Recent list, shows Working while the
agent is compacting and leaves Ready on successful completion. The chapter index
was reviewed with production manifests, including a 27-chapter Conversation, and
now exposes a Most recent shortcut above the chronological arc.

Automated coverage pins chapter derivation, title extraction, date formatting,
chapter index rendering, shared scrolling, manual compaction presentation,
Journey-scoped compaction cards, sidebar activity, Ready attention on success,
Segment frontier republication, provider isolation and hook ordering in the App.
