# v0.2.0-alpha.46 — Where You Left Off

**Date:** 2026-10-12

## Highlights

- **You come back to where you were.** Reopen the app and you land in the conversation you were last working in, not at the Journey's front door.
- **An unsent message comes back with it.** The draft you had half-written is where you left it, attached to the conversation it belongs to rather than stranded somewhere you cannot find.
- **It gives up quietly when it should.** If that conversation was hidden, deleted or is otherwise unavailable, you land on the Journey workspace with no error and no empty screen.
- **It does not undo your tidying.** If you had collapsed a Journey's conversation list before quitting, it stays collapsed.

## Where We Started

The app remembered which Journey you were in and nothing finer. Every relaunch put you at the Journey's workspace, and if you had been working inside a conversation you had to find it again and reopen it.

The cost was clearer than it sounds, because of what came with it. A half-written message is saved against the conversation it was typed in. Reopening the app selected the Journey instead, so the draft was still on disk and simply not on screen anywhere you could reach. Production had a real instance while this was being written: a 203-character unsent message, saved correctly, invisible since the previous session. **Not lost — unfindable**, which is a different problem with the same feeling.

## What Changed

The app now remembers the last conversation you had selected **in each Journey**, and restores it on launch.

Per-Journey rather than one global value, for a reason worth stating: a single remembered conversation is destroyed by the first Journey you switch to, because a conversation selection that does not match the current Journey has to be discarded. Keyed by Journey, the memory survives.

### When it cannot put you back, it says nothing

A remembered conversation can become unreachable in several ways, and they are distinguished internally rather than collapsed into one failure: nothing was remembered; the Journey's conversation list could not be read; the conversation is gone; the conversation is hidden. In every case you land on the Journey workspace — the same place you landed before this release — with no error state and no blank screen.

**A hidden conversation is never silently reopened.** Hiding is a choice, and restoring you to something you had put away would undo it without asking.

### Restoring is not starting

Putting you back somewhere reads. It does not start, provision, restart or wake anything, and no run record moves when it happens.

### The draft needed no new code

The visible draft already follows the selection. Restoring the selection correctly was enough to bring the message back — which is the pleasant kind of discovery, where the feature you were about to build turns out to already exist behind the bug you were fixing.

## Conscious Exclusions

- **Switching Journeys during a session does not restore that Journey's conversation.** The memory would permit it. The restore happens at launch only, because discarding a mismatched selection mid-session is deliberate behaviour from an earlier release and changing it is a separate decision.
- **Only the conversation is restored, not the reading position.** You land in the conversation, at its end, as you would by opening it.
- **The sidebar's collapsed Journeys are still not remembered across launches.** Pre-existing, unrelated, and untouched here.

## What We Learned

**This release broke a shipped promise and then repaired it.** An earlier release guarantees that reloading preserves which conversation lists you had expanded. The first version of this feature had to load a Journey's conversation list to validate the remembered conversation, and loading it opened it — reopening, and then saving, a list the Navigator had deliberately collapsed. **Restoring where someone was must not cost them a choice they made about what they wanted to see.** The repair was to let the list be read without being opened.

**It was found by opening the app, not by reading the code.** Neither review nor the test suite caught it, and neither did this feature's own field check, which passed. It took a deliberate experiment afterwards.

**The first experiment failed because its report was never specified.** A gesture was requested without stating what should be reported back, so the outcome had to be inferred from disk — and a trace left by the app is indistinguishable from the same trace left by a person clicking. The redesign removed human recollection from the critical path entirely: click nothing, read only while the app is closed, and pause to confirm the starting state before anything depends on it. It settled the question in one run.

**An old guard caught a new mistake, and only just.** A rule from the earlier release is pinned by a test, and the first draft of the repair violated it. The test caught the draft by matching an exact phrase — and it matched only because the draft happened to spell the comparison one way rather than the other. The rule is now stated in a form that cannot be sidestepped by rephrasing. **A guard that expresses the right intent can still be one keystroke from being useless.**

## Next Horizon

With this, the series on conversations as first-class workspaces is finished: a disclosure that only discloses, status that names whose work is running, a reversible hide, concurrent work inside one Journey, and now a relaunch that returns you where you were.

The open question from the previous release has not moved: why a finished Pi process sometimes fails to hand its turn back. That remains the one worth answering, and a testable hypothesis about it is now written down.
