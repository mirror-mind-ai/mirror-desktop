# v0.2.0-alpha.22 — Floating Recenter Control

**Date:** 2026-09-27

## Highlights

- Moves the "Return to the latest turn" control out of the central header and into the Conversation viewport.
- Shows it only while the reader is away from the end of the Conversation.
- Keeps the control fixed over the viewport rather than letting it scroll with the transcript.
- Uses a quiet fade-and-lift transition, with reduced-motion support.
- Keeps the control out of the pointer path and tab order while it has nothing to offer.
- Preserves the Mirror history exclusion, where the Conversation stream is not the active surface.

## Where We Started

CR084 gave the Desktop a reliable way to return to the latest turn, but the
control had to live in the central header. That made it technically available,
yet spatially wrong: the reader's attention and hand were in the transcript,
while the affordance lived above it among unrelated controls. The header version
also needed an `available`/`emphasized` split because it could not simply appear
where it was useful without shifting its siblings.

## What Changed

The control now behaves like a map recenter button. The end of the Conversation
is the territory; when the reader drifts away from it, the control appears as a
small point of support over the transcript. Clicking it returns to the latest
turn, after which the control leaves.

The implementation wraps the scrolling transcript in a stable viewport and
anchors the control to that wrapper. That detail matters: an absolutely
positioned child inside the scroller would scroll with the content and disappear
precisely when it should remain available. The new viewport gives the control a
fixed local anchor without disturbing the chat shell's grid layout.

The state model is simpler too. Presence is now the signal, so the old
`available` and `emphasized` contract is gone. `deriveConversationRecenterState`
returns only `visible`, derived from the same away-from-end signal that already
fed the CR084 button.

## Conscious Exclusions

- No new-content badge, count or emphasis. The control means "go to the end", not "something new arrived".
- No runtime scrollbar measurement. A generous fixed right offset keeps the control clear of visible scrollbars without adding layout instrumentation.
- No expansion to Mirror history. That surface hides the Conversation stream and is governed by a different interaction model.
- No change to auto-follow, synchronization, persistence, Mirror append behavior or release infrastructure.

## Validation

The CR was validated on the Dev channel before merge. The Navigator confirmed
that the control appears and leaves at the right moments, does not flicker when
crossing the threshold, responds to search and turn-navigation jumps, reads as
an overlay in light themes, does not intercept scrollbar dragging, follows the
keyboard accessibility contract, and remains absent from Mirror history.

Automated coverage now pins the viewport-vs-scroller structure, the fixed offset
instead of scrollbar arithmetic, the transition and reduced-motion behavior, the
tab-order contract, the narrowed return action, and the removal of the old
header/emphasis contract.

## Next Horizon

RS021 still holds the remaining pre-beta UX polish. The most consequential next
item is CR089, because preserving an interrupted partial response is not just a
visual adjustment: it asks whether the Desktop Conversation may preserve material
that Pi's transcript never committed. That contract should be decided before it
becomes implementation.
