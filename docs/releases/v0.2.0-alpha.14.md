# v0.2.0-alpha.14 — Convergent Turn Synchronization

**Date:** 2026-09-21

## Highlights

- Settles the turn journal before acknowledging the outbox item, removing the latent defect that made every completed turn leave synchronization debt behind.
- Keeps Mirror synchronization internal, surfacing a notice only when durable debt persists after an automatic repair attempt has failed.
- Moves turn finalization out of the renderer into a serialized per-Journey coordinator with atomic, monotonic publication.
- Replaces five overlapping repair paths with one idempotent convergence routine shared by hydration, the repair action and post-terminal completion.
- Converges retained delivery debt for Desktop Conversations, not only for the Journey's dedicated Conversation.
- Reserves the `Message was not sent` banner for runs that genuinely never reached the agent.

## Where We Started

Alpha.13 completed the post-terminal authority model, but sustained use kept showing a synchronization notice after ordinary turns. Four refinement series and roughly twenty-five Change Requests had each corrected one pair of disagreeing replicas, and each correction was individually sound. The notice still returned.

The pattern itself was the diagnosis. The same conversation truth lived in base renderer state, a per-Journey runtime snapshot, a persisted projection, the turn journal, the outbox, Pi JSONL and the Mirror database. Every pair needed synchronization logic, the renderer orchestrated the whole transaction inside a React component, and fail-closed validation designed for durable writes had been extended to presentation. The product punished the user for its own internal disagreement.

## What Changed

Turn finalization now runs in a renderer-independent coordinator. Work is serialized per Journey, executed by a single writer, and published atomically. A committed turn can never regress to pending, and late convergence for an older run upgrades the presented conversation instead of replacing it.

Synchronization status derives exclusively from durable evidence: the turn journal, the exact outbox and known native occupancy. In-memory projections can inform what is rendered but can no longer fabricate debt. The notice additionally requires recorded failure evidence, so the ordinary settlement window stays silent while genuine, persistent failures remain actionable.

Recovery collapsed into one convergence routine covering legacy items, Pi-backed reconstruction and projected-journal resume. Running it on a synchronized Journey performs zero writes. A refusal because native execution is active is a silent deferral, not a failure, and an already-settled record or a vanished outbox item is recognized as already converged.

The deepest correction came last. The native journal transition to `settled` requires the exact outbox item to still exist, but the live path acknowledged the item first. Every completed turn therefore delivered to Mirror and then failed its final journal advance, leaving debt that convergence cleaned up seconds later. Settling before acknowledging removed that defect at its source.

## Validation

- An executable multi-turn contract that models the native journal contract and covers consecutive turns, navigation, restart, injected append failure, deferral under an active successor, delayed older-run convergence and a zero-write no-op proof.
- Five release-shaped homologation rounds on production data, each failure reopening the responsible Change Request rather than being absorbed by acceptance.
- Recorded durable evidence for every homologated run: journal settled, empty outbox and exact message pairs present in Mirror.
- Complete frontend and Rust suites under both the Stable and evaluation feature sets, TypeScript/Vite production build, locked Cargo validation and roadmap consistency.

## Conscious Exclusions

- This release does not surface provider terminal error text in the GUI; that remains CR054.
- This release does not redesign effective-model explanation in Settings; that remains CR053.
- This release does not change Mirror Core, durable schemas or the Pi invocation contract.
- This release does not retry providers, switch providers or models, or infer alternate credentials.
- This release does not promote stable distribution, notarization, app-store delivery, Windows/Linux packaging or production Mirror data mutation.

## What We Learned

When many disciplined corrections fail to stabilize one behavior, the defect is usually not in the corrections. It is in the space of states they are trying to tame. Certifying components while the journey keeps failing is a sign that the unit of acceptance is wrong.

Idempotent pipelines do not need choreography. They need convergence. Comparing desired durable state with observed state and closing the difference is simpler and safer than orchestrating each frontier, and it makes the happy path the same code as the recovery path.
