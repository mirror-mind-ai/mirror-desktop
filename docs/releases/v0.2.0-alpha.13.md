# v0.2.0-alpha.13 — Post-Terminal Continuity

**Date:** 2026-09-20

## Highlights

- Makes only exact active `reserved` or `running` Pi execution block a Journey Conversation.
- Releases same-Journey successor admission as soon as Pi terminalizes, even when projection, journal, Segment, outbox, Mirror, acknowledgement or presentation work fails afterward.
- Keeps post-terminal evidence visible and recoverable without letting journal or projection state disable the Composer.
- Prevents late settlement or cleanup for an older run from replacing, releasing or misclassifying a newer run.
- Certifies completed, cancelled, provider-failed and process-died outcomes across all seven secondary frontiers with a bounded 4 × 7 matrix.

## Where We Started

Alpha.12 corrected one provider-error path, but sustained use exposed the broader authority defect underneath it. Pi could already be terminal with its transcript preserved while Desktop still retained a finalizing lease or journal-derived gate. A projection, delivery or acknowledgement failure after native completion could therefore leave the Composer unavailable until the application restarted.

That behavior contradicted the terminal-aligned model established in Alpha.10: durable views and delivery debt are important evidence, but they are not active execution.

## What Changed

Native occupancy now distinguishes active execution from post-terminal finalization. Exact open `reserved` and `running` executions may block a Journey; terminal entries with released process capacity do not. Unknown occupancy remains fail-closed while bounded inspection completes.

Conversation availability no longer derives admission from post-terminal journal state. Terminal journal records remain available for diagnosis and explicit model-free recovery, but they cannot independently set `canSend` to false.

Post-frontier settlement is now exact and run-scoped. A late Mirror receipt for an older run merges only that receipt into the newest persisted projection. It preserves successor messages, reconciliation state, terminal and Steering evidence, metadata and checkpoint identity. Conflicting receipt authority is rejected without partial mutation.

Frontend publication follows the same successor-safe rule. Older callbacks may finish durable work silently, but they cannot replace the successor transcript, Composer, runtime state, notice, lease or settlement diagnostic. Diagnostics are keyed by exact Journey, run and turn identity.

## Validation

RS019 validation covered the full post-terminal authority surface:

- Complete 4 × 7 matrix for `completed`, `cancelled`, `provider_failed` and `process_died` across projection, journal, Segment, outbox, Mirror, acknowledgement and presentation frontiers.
- Same-process successor admission after terminal failure without application restart.
- Exact old-debt retention and successor-safe late cleanup.
- Cross-Journey capacity proving released finalization debt consumes no active slot.
- Pi-backed relaunch reconstruction without provider work.
- Complete frontend and Rust regression suites, TypeScript/Vite production build, locked Cargo validation, roadmap checks and private-data-free evidence validation.
- Isolated source-built DEV rehearsal with exact ordinary-DEV restoration and stable-app recovery.

## Conscious Exclusions

- This release does not surface provider terminal error text in the GUI; that remains CR054.
- This release does not redesign effective-model explanation in Settings; that remains CR053.
- This release does not retry providers, switch providers or models, or infer alternate credentials.
- This release does not weaken unknown native occupancy or exact Journey/thread/generation/Pi-session binding.
- This release does not promote stable distribution, notarization, app-store delivery, Windows/Linux packaging or production Mirror data mutation.

## What We Learned

Terminalization and settlement are different boundaries. The user should wait only while an exact native writer is genuinely active. Projection, synchronization and presentation work may continue afterward, but retaining evidence must never turn secondary debt back into execution authority.

Run identity is equally important after terminalization. Releasing occupancy early is safe only when every late callback and cleanup operation remains exact, idempotent and incapable of altering a successor.
