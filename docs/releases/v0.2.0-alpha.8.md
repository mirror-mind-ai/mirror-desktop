# v0.2.0-alpha.8 — Multiple Conversations per Journey

**Date:** 2026-09-16

## Highlights

- Keeps the established Journey workspace while revealing bounded associated Desktop and Mirror Conversations inline beneath the owning Journey.
- Creates independent Desktop Conversations with dedicated thread, generation, Pi session, Mirror authority, drafts, transcript, and recovery lifecycle.
- Adds editable unique `New Conversation #n` titles, Desktop and Mirror rename actions, and explicit title recommendations from bounded recent turns.
- Makes Mirror history actionable through canonical rename, bounded Terminal recall, and an editable unsent handoff into a new Desktop Conversation.
- Preserves complete long histories through Pi-owned compaction checkpoints, bounded technical Segments, and explicit earlier-history loading.
- Adds exact reset and deletion lifecycles with fail-closed interruption recovery and no automatic prompt replay.
- Unifies Desktop and Mirror detail surfaces while keeping active Desktop Conversation identity persistently visible as transcripts scroll.
- Keeps attachments scoped to the selected Journey so an unrelated running Journey cannot disable an idle Conversation composer.

## Where We Started

Mirror Desktop had one dependable Journey-level conversation. That root workspace already carried exact Pi and Mirror authority, durable settlement, recovery, Steering, and bounded concurrency, but every additional thread of work had to share the same conversational history. Mirror conversations created through Terminal were visible only outside Desktop, while long Desktop histories were still represented as one conceptual stream even after Pi compacted its active context.

The need was not simply to add more chat rows. A second Conversation had to preserve the Journey as its semantic territory without inheriting sibling transcripts, weakening one-lease-per-Journey execution, or pretending that generic Mirror history was an executable Desktop session. Continuation also needed to remain explicit: recalled material is evidence, not privileged instruction, and a handoff is a new context rather than silent resumption.

## What Changed

Each Journey now keeps its existing root workspace and can expand an inline bounded catalog of associated Conversations. Desktop entries resolve to exact application-owned authority. Mirror entries remain read-only history surfaces with source actions. The sidebar stays resizable by pointer and keyboard, preserves sibling Journeys, and loads catalog metadata without eagerly loading every transcript.

A new Desktop Conversation is provisioned without calling a model or creating a synthetic greeting. The creation form proposes the first available `New Conversation #n` title, permits editing, normalizes whitespace, and rejects duplicates without case sensitivity across visible Desktop and Mirror entries. Desktop titles can later be renamed without changing technical generation or Mirror names. An explicit recommendation action may ask the configured model for a bounded title derived from recent turns; it uses no persistent session or tools and only fills the form for user confirmation.

Desktop Conversations own separate drafts, threads, generations, Pi sessions, generated Mirror conversations, transcripts, Segments, and lifecycle journals. Reset creates a fresh generation inside the same Conversation while preserving prior generations. Deletion is limited to Desktop children, requires confirmation, and removes only exact catalog, session, projection, Segment, draft, and generated Mirror authority. Creation, reset, deletion, and handoff recovery converge after interruption without replaying a prompt or process.

Mirror history can be renamed canonically through released Mirror APIs, opened in Terminal through a bounded recalled context, or used to prepare a handoff. A handoff creates destination authority first and then publishes an editable unsent prompt. Nothing runs until Send. The eventual agent turn names the exact Journey and source, applies the disclosed recall bound, treats recalled text as source material, and does not claim transcript import, synchronization, or exact prior-session continuation.

Pi remains the sole model-context and compaction authority. Completed Pi checkpoints are projected as technical Segments inside the same Conversation and generation. Desktop opens only the current Segment initially, offers explicit earlier-history loading, rejects malformed or cross-authority evidence, and preserves complete history above production-scale message and byte boundaries. Segment metadata distinguishes a truly empty Conversation from an empty current Segment with earlier history.

Desktop and Mirror landing states now share one visual grammar for status, type, title, metadata, explanation, actions, and secondary history. Active Desktop Conversations retain their title in the persistent Journey header while the transcript scrolls. Attachment selection, removal, and drag-and-drop depend on the selected Conversation's runtime rather than aggregate activity in unrelated Journeys.

## Conscious Exclusions

- The Journey root workspace is not converted into a child catalog entry or migrated into the first Desktop Conversation.
- Mirror history is not executable in Desktop and does not gain a composer, exact Pi session authority, transcript import, synchronization, divergence detection, or automatic merge.
- A Desktop Conversation does not automatically inherit messages, drafts, attachments, or active model context from the Journey root or sibling Conversations.
- One Journey still owns at most one reserved, running, or finalizing Pi lease across all of its Conversations.
- Pi compaction does not create a new Conversation or generation, and Desktop does not perform its own summarization.
- Title recommendations never rename automatically and do not run during creation.
- Apple Developer ID signing, notarization, native arm64 packaging, stable-channel promotion, and app-store distribution remain outside this alpha release.

## What We Learned

Conversation identity is useful only when its boundaries are visible and technically enforceable. The Journey provides shared semantic territory, but each Desktop Conversation needs independent conversational memory. Treating those as the same kind of context would either isolate the agent from the project or leak one thread into another.

Mirror history also became more useful when the interface stopped pretending that every visible row had the same capabilities. A common visual grammar can coexist with different authority: Desktop offers execution and composition, while Mirror offers source inspection and explicit continuation routes. Uniformity should clarify difference, not erase it.

Long-history behavior reinforced the same principle. A Segment is a loading boundary inside one Conversation, not a user-facing identity. Keeping Pi authoritative for compaction while Desktop remains authoritative for bounded projection preserves both context truth and complete recoverability.

## Next Horizon

Observe multiple-Conversation operation through the alpha channel, especially naming, handoffs, reset and deletion recovery, and explicit Segment loading. The next planned Conversation Spaces candidate is Persona Conversation Spaces, followed by Voice Prompt Composition. Any broader synchronization or revisioned working-copy import should begin only when Mirror exposes an explicit bounded source-authority contract.
