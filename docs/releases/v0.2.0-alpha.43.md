# v0.2.0-alpha.43 — Where the Work Is

**Date:** 2026-10-09

## Highlights

- **Opening a group no longer moves you.** Expanding a Journey's conversations reveals them without changing where you are or what is loaded.
- **Running work says whose it is.** The status mark now distinguishes work in the Journey's own workspace from work inside one of its conversations, and activating it takes you to the owner.
- **A conversation can be put away.** *Hide from List* removes it from the sidebar and nothing else. It is reversible, and it says so.

## Where We Started

You named the sidebar the last fragile point of the app, and the three symptoms turned out to be separable.

**Opening a group was a journey change.** One click did two things: it revealed a Journey's conversations *and* it made that Journey current — unloading the transcript you were reading and retargeting the composer. If a turn was running where you had been, you lost sight of it by doing nothing more than looking around. One Journey's conversations could be open at a time, so looking at a second group closed the first.

**The status mark could not say whose work it was.** A conversation and its parent Journey share one identifier, so a single mark served both. It could tell you that *something* in this Journey was running. It could not tell you *what*, and it led nowhere.

**The list grew and could only be truncated.** After six conversations the rest were folded behind *Show N more* — a cap the app chose, not one you set. There was no way to say *I do not need to see this one*, and the only thing resembling it was Delete.

## What Changed

### Looking is not going

Expansion and selection are now separate. Opening or collapsing a group changes **no** selected Journey, no selected conversation, no composer target, no loaded transcript, and no run ownership. Several groups can be open at once, and the set of open groups survives a restart.

Clicking a *conversation* still takes you to it — that is navigation and always was. The change is that the triangle beside a Journey name does one thing instead of two.

Keyboard and mouse now behave identically in both directions. They had diverged, and the divergence only showed up when collapsing.

### The mark says which conversation, and takes you there

When work is running inside one of a Journey's conversations rather than in the Journey's own workspace, the Journey's mark is drawn **inside a containing contour** — the same spatial idea the app already uses for nesting — and the surface says the work is in a conversation.

In the sidebar that mark is now a **control**. Activating it selects the Journey and the owning conversation in one act, and it works whether the sidebar is compact, the Journey unexpanded, or the conversation hidden. A signal that leads nowhere is of little use when what you want is to get back to the work.

The header keeps the plain signal, without the control. Work in the Journey's own workspace looks exactly as it did before — the addition appears only when there is nesting to show.

**The Journey row is the guaranteed carrier.** There are three ways a conversation can be invisible — a compact sidebar, an unexpanded Journey, and now hiding — and running work must never be representable *only* on a surface you can turn off. That row cannot be configured into silence, which is why it exists in this shape.

### Putting a conversation away is not deleting it

*Hide from List (can be revealed)* appears in the conversation menu, reachable by right-click or `Shift+F10`. The hidden set gets its own count and its own section, with a sentence that says plainly that nothing was deleted — visible before you open anything, because the doubt arrives before then.

Three things were deliberate:

**Your choice and the app's cap stay separate.** *Show N more* now counts only the visible list, so a truncation nobody chose can never fold in a decision you made.

**A hidden conversation you are currently inside still appears, marked.** Otherwise the list would deny the existence of the conversation on screen.

**Hiding is never blocked.** It changes no transcript and no record, so a conversation that needs attention — which has no other actions at all — can still be put away. It is a view preference, and it stays one.

Provenance is untouched: old Desktop conversations and Mirror Core history remain distinguishable wherever they appear, because hiding never alters an entry.

## Conscious Exclusions

**Two conversations still cannot run at once in one Journey.** Native work remains one run per Journey. This release makes ownership legible, which is what has to exist before concurrency can be admitted safely — but it does not admit it. Starting a turn while a sibling conversation is working is still refused.

**A Journey's own workspace cannot be hidden.** It is not a list entry, and it is the row that carries running work. Making it hideable would contradict the guarantee above. An acceptance criterion that asked for it was withdrawn rather than implemented.

**Returning to the conversation you left is not fixed here.** After a restart the app can disagree with itself about which conversation you were in. This release is what made the disagreement visible, and it is recorded as its own work rather than absorbed into a fix it does not belong to.

**A hung-but-live run still says nothing.** Unchanged from the previous release, and still recorded.

**Nothing is deleted, archived, migrated or pruned.** Hiding is a preference stored beside your pins and theme. A hidden conversation whose preference file becomes unreadable comes back visible, with pins and theme intact — the conversation itself is never at risk.

## What We Learned

**An invariant is better made true by construction than by vigilance.** Hiding filters what is drawn and never touches the stored list of conversations. That one constraint is what makes the rest hold: the route to running work still finds a hidden conversation, because the data it reads was never filtered. A test asserts the storage layer contains no mention of visibility at all — the moment it *could* filter, the guarantee would depend on care rather than on structure.

**Two surfaces disagreeing is a sharper fault than one surface going quiet.** It was the honest description of the restart problem above, and it is why a hidden-but-open conversation is forced to appear.

**A validation step that cannot fail is not a validation step.** Writing the field script for the ownership work is what exposed a claim in it that was simply wrong — that status survived a relaunch. It does not: quitting ends every run. The claim was withdrawn at its source, in the code comments as well as the record, and the behaviour it had wrongly justified was kept only because it is correct for a different reason.

**Separating two things that were fused is cheaper than making the fused thing smarter.** Expansion and selection, the app's cap and your choice, a signal and a control. None of the three needed new cleverness; each needed one thing to stop being two.

## Next Horizon

Whether one Journey can host two conversations working at once — the question this release was built to make answerable. Before that, returning you to the conversation you actually left.
