# v0.2.0-alpha.26 — Interrupted Work Stays Legible

**Date:** 2026-09-30

## Highlights

- Preserves work a cancelled agent turn already performed when the Conversation is rebuilt.
- Shows only prose that was in flight at interruption as an explicit interrupted fragment, never as transcript.
- Keeps the original request's durable identity so its turn-scoped evidence remains attached after reload.
- Restores agent commentary as a visible, ordered reading trail instead of collapsing it into the final answer or hiding it.
- Makes the macOS red close control hide the window without terminating Mirror Desktop; Quit remains the explicit exit path.

## Where We Started

A cancellation could make real work disappear from the Conversation. Pi had recorded operations,
results and comments, but the rebuilt Desktop surface could discard them when no completed answer
existed. If cancellation arrived while prose was streaming, that prose vanished too. Returning to a
Journey could compound the loss: the evidence that held an interrupted fragment was rejected during
persistence loading because its original harness assistant message was no longer part of the
Pi-derived surface.

Adjacent Agent Comments had a second problem. Their boundary existed in the Pi stream but was
thrown away before rendering. A comment that described work under way could visually collide with
the closing response, and reconstructed turns had no honest visual register for comments that did
not answer the request.

On macOS, closing the main window could also terminate the process — conflating hiding a workspace
with explicitly quitting the application.

## What Changed

**Interrupted work is reconstructed from its real sources.** When Pi and the durable turn record
show that a run was cancelled or failed, Desktop rebuilds the operations and reasoning already
committed by Pi. The decision is made per run, not per entry, so all work in the interrupted run is
kept even when no individual entry carries a reasoning block. System entries no longer incorrectly
shorten the matching window.

**In-flight prose is evidence, not invented transcript.** The surface preserves only the text after
the last agent-comment boundary. It appears in an amber `Interrupted` region with an explicit
interruption suffix, rather than becoming an assistant message Pi never wrote. Cancelling between
steps therefore produces no false fragment. The supporting evidence now survives leaving and
re-entering a Journey; stale derived fragment maps are cleared rather than pointing at missing
anchors.

**A request keeps its turn identity.** Reconstructed interrupted requests bind to their original
harness user-message identity. That allows turn-scoped steering and other evidence to resolve to
the request that created it. The assistant side deliberately remains unbound: Pi can record several
assistant entries for one run, and inventing a one-to-one identity would be false.

**Agent comments have a reading register.** The stream carries its existing assistant-message-end
boundary into the reducer. Comments with later work become a visible ordered trail; only a completed
turn's genuine closing comment may be treated as an answer. Cancelled and failed runs never gain an
answer they did not produce. Restored comments follow the same rule.

**Close and quit now mean different things.** The app owns the macOS Quit item and only that path
asks to terminate. The red window control hides the window instead. This preserves the background
process and its work while making Quit explicit.

## Conscious Exclusions

- Pi JSONL remains transcript authority; no text Pi did not commit becomes a Conversation message.
- A fragment discarded by older builds cannot be backfilled: Pi never held that in-flight prose.
- Recovery remains bounded by the turn-journal retention window.
- The macOS Dock Quit path retains the native-framework limitation already documented for its
  termination interception; application-menu Quit is the controlled explicit path.
- Steering corrections that become indistinguishable from ordinary Pi user entries after reload are
  not changed here. That finding is captured separately as CR097.

## What We Learned

Interruption was not one loss but three: operations, already committed narration and prose in
flight. The first two belong to recoverable Pi evidence; the last needs a deliberately separate
surface or it becomes fabricated transcript. Treating those as one problem hid the authority
boundary.

Persistence validation also must use the same authority as persistence writing. An interrupted
turn cannot have the assistant message that its evidence is keyed by; demanding it at load time
silently erased exactly the evidence the writer had correctly recorded.

The same discipline clarified commentary. The right distinction is structural rather than
linguistic: a comment followed by work is a note; a completed turn's closing comment can be an
answer. Nothing needs to be hidden to preserve that distinction.

## Validation

The Navigator homologated all three interrupted-response phases in the Dev build. A real
leave-and-reenter run preserved the 603-character interrupted fragment, its empty anchor, request
identity, comment roles and cancelled operations. Earlier cancelled work remains recoverable where
the journal retains its record; only an older fragment lost before this fix remains irrecoverable.

Automated coverage includes interrupted-action reconstruction, fragment selection and rendering,
request identity, restored comment roles, stream boundary handling and persistence of interrupted
evidence. The release candidate runs the full frontend, Rust, preflight and signed alpha-build
gates before publication.

## Next Horizon

CR097 is the remaining captured RS021 refinement: a correction sent during an active run must
remain recognisable as a correction after reload rather than reading as a new unanswered request.
