# v0.2.0-alpha.11 — Conversation Search and Close Safety

**Date:** 2026-09-19

## Highlights

- Adds Conversation search from the top bar, with match counts, next/previous navigation and yellow highlighting over visible matches.
- Adds a turn navigator that lists user turns newest-first with avatar, styled turn number and plain-text quote snippets.
- Keeps search and turn navigation read-only and scoped to the loaded active Conversation.
- Coalesces Composer draft persistence so typing stays local while latest-state durability happens after a bounded idle interval and explicit flush boundaries.
- Restores ordinary main-window close behavior when the app is idle.
- Warns before closing while agent work is active or finalizing, and requires explicit confirmation to close anyway.
- Improves light-theme contrast for the new Conversation controls and close-confirmation explanation surfaces.

## Where We Started

Alpha.10 stabilized transcript authority and continuity around the native Pi session. That made long Conversations more trustworthy, but not yet easy to revisit. A durable transcript that can only be traversed linearly still creates friction when the Navigator needs to find an earlier term, return to a specific user prompt or resume orientation inside a long working thread.

Continued daily use also exposed two smaller operating-boundary problems. First, rapid Composer typing was coupled too directly to durable draft writes. Second, the close path was not coherent: the main window close control could fail to close the app, while active agent work still needed an explicit warning before ordinary quit or close actions could interrupt it.

## What Changed

Conversation search is now available from the top bar. It searches the loaded content of the active Conversation, reports honest match state, supports previous/next movement and highlights found terms in yellow without changing transcript content or authority.

Turn navigation is now a separate top-bar control. It opens a right-side floating panel over the Conversation surface and lists user turns from newest to oldest. Each row uses the user's avatar, a styled turn number and a cleaned plain-text quote snippet derived from the user's own message. Assistant turns are intentionally omitted so the navigator works as a prompt-oriented way back into the conversation.

Search and turn navigation remain presentation tools. They do not search across Journeys or unrelated Conversations, invoke a model, generate summaries, mutate messages, alter Pi JSONL authority, append Mirror content or load unbounded history silently.

Composer draft persistence now separates immediate writing from durable storage work. The visible Composer and destination-keyed in-memory state update immediately, while the durable draft snapshot is coalesced around the latest state after a bounded idle interval. Explicit flush boundaries preserve recovery expectations on blur, destination change, accepted send and app closure.

The application close boundary now has one clearer contract. When no agent work is active or finalizing, ordinary close routes — including the main window close control — flush drafts and close. When active or finalizing agent work exists, Mirror Desktop prevents the close request and shows an application-owned confirmation dialog. Cancelling keeps the app open; confirming flushes drafts and closes anyway.

Light-theme contrast was tightened for the new surfaces: Conversation search and turn panels, fallback avatars inside the turn navigator, the close-confirmation explanation box and related controls now use the light-theme semantic tokens instead of dark-mode assumptions.

## Validation

Local preparation covered the focused behaviors introduced in this release:

- Conversation search and turn-navigation model tests.
- Message rendering and linkification tests for highlighted search terms.
- Application theme contrast tests for the new and adjusted surfaces.
- Composer draft integration and coalescing tests.
- Frontend production build through `tsc && vite build`.
- Isolated development bundle rebuild for Navigator validation.

The Navigator validated the Conversation search and turn navigator in the rebuilt development app, including highlighted matches, inline close controls, newest-first user turn ordering, plain-text quote snippets and read-only behavior. The Navigator also validated the close-boundary correction, including ordinary close behavior and improved light-theme contrast in the close dialog.

## Conscious Exclusions

- Search is not semantic search and does not use embeddings or model-generated summaries.
- Search does not cross Journeys, persona destinations or unrelated Conversations.
- Turn navigation lists user prompts only; it does not summarize assistant responses.
- The feature is scoped to loaded/materialized Conversation content and does not silently load unbounded history.
- The close confirmation does not cancel, settle, retry or repair active agent work; it only asks whether to close anyway.
- This release does not promote stable distribution, notarization, app-store delivery, Windows/Linux packaging or production Mirror data mutation.

## What We Learned

Once transcript authority is stable, the next usability gap is navigation. A long trustworthy Conversation still needs local affordances for finding and returning without changing what the transcript means.

The same principle applies to close behavior. Closing the app is not an agent-control action, but it intersects agent work. The safe boundary is to make the consequence explicit without overloading close with cancellation, retry or settlement semantics.

Draft persistence also benefits from separating user perception from durability mechanics. The Composer should feel like a writing surface first. Durability should preserve the latest meaningful state at clear boundaries, not turn every keystroke into storage pressure.
