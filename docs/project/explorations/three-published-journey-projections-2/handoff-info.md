# Handoff Info: Three Published Journey Projections

## Handoff Summary

One umbrella Builder handoff for a three-altitude Journey projection system. Operational is an Ariad-owned deterministic read model of roadmap CV/DS/US/TS hierarchy, active work, Exploratory Stories and Refinement Stories. Tactical and Strategic are explicit Pi interpretations using Mirror context and a versioned Nautilus Method synthesis profile. All three publish versioned JSON snapshots inside the selected Journey through secure, atomic, extension-scoped Mirror infrastructure and are read without mutation authority by Harness. Execution is gated: specify and probe Mirror first; implement, release and install Mirror in another session; verify the unchanged return probe against production; only then implement Nautilus Protocol, Method, Extension and Harness.

## Attractors

- **Published Journey synthesis** (`proposed`)
  - An explicit Navigator command asks Pi, operating with Mirror context, to generate a candidate Tactical and/or Strategic reading. A deterministic Mirror/Nautilus publisher validates and atomically writes a versioned projection inside the selected Journey. Harness only reads that published projection. Operational sources remain canonical evidence; the JSON is canonical for the currently published derived reading, not canonical truth about the Journey.

## Experiment Status

**Consumer-driven Mirror release return probe** (`proposed`)

Before implementing Mirror Core, Builder materializes Mirror Journey Projection Contract v1, representative Ariad fixture data, expected Operational JSON, black-box security and atomicity scenarios, an executable probe against the installed Mirror CLI/API, and RETURN-CONTRACT.md. The separate Mirror release session must make that probe pass through TDD, CI, versioned release and production installation. On return, Nautilus reruns the unchanged probe against the installed version; Protocol, Method, Extension and Harness work remains blocked until it passes.
