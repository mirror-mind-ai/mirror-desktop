## Continuous Thickening Narrative

Origin. CR105 shipped a surface that was faithful and operational, answering the engineer's question of what the agent actually perceived. Seeing it working revealed a conceptual mismatch: the Navigator needed the opposite direction. The agent assembles the panorama of a workspace on demand, while the Navigator clicks one file at a time, so the asymmetry is not that the agent sees too little but that it grasps more than the human does.

Why genericity was the structural error. Only the Journey knows its own shape. Measured on two real Journeys: vida-economica (83 files, 21 directories) is shaped as a monthly cadence, while livro-lideranca-soberana (932 files, 517 directories) is shaped as a grid of sessions crossed with revision generations plus a part-chapter-stage pipeline encoded in numbered folders. The file tree can render only containment, which is the dimension carrying the least meaning in both. The exploration proved the inference risk on itself: reading vida-economica's cadence from directory counts produced a confident wrong claim that cycle 202609 was incomplete, when docs/estado-atual.md reports the ritual closed and the real cadence columns are root markdown files that migrated from .txt to .md after 202606. Full shell access did not prevent the error. Declaration must replace guessing.

What already exists and must be honoured. livro-lideranca-soberana carries docs/surface-status-do-projeto.md, a prose contract declaring sources of truth, form (a single table with only the current chapter expanded), the current-chapter rule, three states, six ordered stages, persistence under workflow_stages, and invocation, over data in livro/estrutura.yml and livro/status.yml. It explicitly forbids inferring state from conversation memory or stale transport files. vida-economica carries its workflow in prose too, in docs/rotina-mensal-pagamentos.md, including trigger, activation reading list, resume rule, an ordered rhythm, an authority boundary where payments are always executed by the human, and three phase tables. Both Journeys already have workflows written; livro additionally declared a surface. Insufficient material will be the rare outcome, and the setup prompt's usual work is finding rather than inventing.

Naming. Workflow is confirmed by three measurements: the Nautilus method uses the word once and only to deny it, so nothing is borrowed; the Navigator had already named the key workflow_stages in his own status.yml; and it appears in 263 messages, 17 memories and 4 identity entries. Panorama was rejected despite being his word, because Mirror already uses it for the cross-Journey overview. Context names the kept CR105 surface, chosen over Attention because the surface can only prove tool-evidenced reading and declares shell as a permanent blind spot. Field and territories both retire, since Human Territory makes territories a Nautilus term as much as field.

Measured implementation constraints. omitted_workspace_component in src-tauri/src/main.rs rejects any path component beginning with a dot, so .mirror and dotfiles are invisible to the existing bounded reader; the manifest therefore sits non-dotted at the Journey root beside the JOURNEY.md both canonical Journeys carry, and read_journey_document_at already validates paths and rejects symlinks, so a manifest reader can reuse that same validate_document_relative_path check. A new bounded Rust command is nonetheless required, because documentation_preview_kind answers unavailable for every extension other than md, markdown and txt, so the existing reader cannot return JSON at all. The correction matters twice over, since the canonical Journey's existing manifesto.json for the proof lives under build/, which omitted_workspace_component also excludes. No YAML parser exists in package.json or src-tauri/Cargo.toml, which carry serde_json and toml, so JSON costs nothing and matches the .mirror/projections/current.json precedent. ArtifactMarkdown.tsx already renders headings, lists, code, blockquotes, tables with per-column alignment and inline strong, emphasis and code, which is exactly what the canonical surface uses, so there is no new rendering work. App.tsx already passes journeyRoot into the surface from CR105. The manifest declares schemaVersion, title, surface path, contract path and source paths, and no semantics.

Staleness and honest absence. Comparing the rendered surface mtime against declared sources needs no persistence, asks no arithmetic of the agent, and fails safe toward possibly stale; hashing the canonical case's three sources costs 0.191 ms per check and remains the upgrade if checkouts rewriting mtime cause false alarms. Rust must supply the raw facts and a pure function under src/domain must derive the state, which is exactly how tacticalStale is already produced in journeyProjections.ts by comparing snapshotId; nothing may be computed in a useEffect. The requirement comes from measured failure: this Journey's own .mirror/projections/current.json reported updatedAt 2026-09-25 while the exploratory story was thickened repeatedly on 2026-10-01, every call failing schema_validation_failed, so a file named current sat six days stale announcing nothing. The surface must degrade by showing absence rather than presenting stale content as fresh.

House rule for the setup button. src/tests/tacticalJourneyWorkspace.test.tsx asserts that a Journey-projection surface shows staleness while carrying no form, input, textarea, button or select, and that its source contains none of invoke, generatePacket, AgentRun, useEffect, localStorage or sessionStorage, nor dangerouslySetInnerHTML. JourneyArrivalSurface does carry buttons, but they only prefill the composer through onChoose, with copy stating that nothing is sent until the Navigator decides. The rule is therefore no invocation, no hidden state and no side effects, while prefill is permitted. The setup button composes a message rather than running the agent, so it sits on the permitted side, and the prompt it writes must forbid inventing a workflow and must make insufficient material a descriptive observation rather than a dead end.

Direction of authority. Existing .mirror/projections flow from Mirror into the Journey, pushing Mirror-owned state down. The Workflow surface flows the opposite way, with the Journey declaring its own shape up to the app, which is why it does not live in that directory.

Scope. The first slice covers only the canonical livro-lideranca-soberana case. The workspace tree stays with the Context tab, since CR105 already marks read files on it, leaving Workflow pure as the Journey's declared view. The artifacts id persists as selection state and the new tab needs its own id. Guiding a Navigator whose Journey has not yet crystallised a view is deferred to its own exploration, already constrained by measurement: estrutura.yml first appears in conversation on 2026-07-27, the stage vocabulary on 2026-07-30, workflow_stages only on 2026-09-20 and the named surface contract on 2026-09-30, so roughly two months separate first structure from declared view. The view is a late crystallisation, which rules out onboarding that begins by asking someone to declare one.

Superseded material. Two earlier branches of this exploration were displaced by the canonical case and must not be read as scope. An attractor about accesses and shared language (URLs, databases, servers, glossary) described the direction of growth, not the first slice. An experiment about extracting URLs and file paths from assistant text without an LLM was measured as affordable (worst production session 112 MB in 820 ms, 83 distinct URLs and 714 distinct paths across 34 sessions) but was set aside once the Journey-declared surface proved the better locus; its circularity caution still stands, since the agent returns to what the briefing told it to read.

## Experiment Proposal

**Stand the canonical Journey's own status surface in a Workflow tab and see if one glance settles the asymmetry** (`proposed`)

Take livro-lideranca-soberana exactly as it is. Add the three contract artifacts without changing the Journey's structure: keep docs/surface-status-do-projeto.md where it already lives, have the agent write its rendered table to a markdown file, and declare both plus livro/estrutura.yml and livro/status.yml in a non-dotted JSON manifest at the Journey root. Render that markdown in a new Workflow tab through the existing ArtifactMarkdown, show staleness from mtime supplied by Rust, and offer a setup button that only prefills a prompt. The experiment passes if the Navigator opens the tab and grasps where the book stands without clicking into any file, and if a deliberately edited status.yml makes the tab announce itself stale rather than presenting old content as current. It fails if the app needs to understand any of the Journey's vocabulary to render, if staleness is computed in a useEffect, or if the surface reads as a status report the app composed rather than the one the Journey declared.
