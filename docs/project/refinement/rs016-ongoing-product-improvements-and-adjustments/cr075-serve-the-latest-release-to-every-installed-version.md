# CR075: Serve the Latest Release to Every Installed Version

**Status:** done
**Driver:** @alissonvale
**Delivery:** `refinement/rs016-cr075-update-to-latest`

## Problem

After Alpha.16 was published through the CR074 route, the Navigator on
Alpha.14 was offered Alpha.15, and only after installing and opening Alpha.15
was offered Alpha.16. Updates arrived one hop at a time.

The cause is the CR074 retention policy. `deriveRetainedVersions(...)`
returned only the latest previously published version plus the release, so
each publication rewrote just two manifest chains. Older chains kept whatever
they served last, producing a chained ladder on the endpoint:

```text
alpha.13 -> alpha.14
alpha.14 -> alpha.15
alpha.15 -> alpha.16
alpha.16 -> alpha.16
```

Remote inspection on 2026-09-22 confirmed the ladder reached back to
`alpha.8 -> alpha.11`.

## Expected Behavior

The updater invariant is: **every manifest path for a version an installed
application might be on serves the latest published release.** A user two or
ten versions behind updates in exactly one hop.

- The retained set is derived from Git tags: every published version strictly
  below the release, plus the release itself. No hand-enumerated version
  lists.
- Versions above the release are excluded, so republishing an older release
  can never downgrade the manifest chain of a newer one.
- The blocking post-publication verification continues to poll every derived
  path, which now proves the one-hop invariant for all installed versions.

## Scope

- `deriveRetainedVersions(...)` in `scripts/release_deploy.mjs` returns the
  full published set below the release plus the release.
- Regression tests in `src/tests/releaseDeploy.test.mjs`: the chained-update
  case (an application two versions behind must have its manifest rewritten)
  and the downgrade guard.
- One-line invariant in `docs/update/alpha-channel-governance.md`.
- Operational repair: republish Alpha.16 through the corrected route so every
  served manifest chain points to `0.2.0-alpha.16`.

## Exclusions

- No change to artifact retention (all manifests point to the latest artifact;
  older artifacts remain governed by existing retention rules).
- No new channel, key or endpoint.
- No Mirror data or app data mutation.

## Implementation Evidence

- `deriveRetainedVersions` now returns every parseable published tag strictly
  below the release, numerically sorted, plus the release. Tags above the
  release are excluded (downgrade guard).
- Tests: chained-update regression (a version two hops behind is rewritten)
  and downgrade guard; 20 route tests and the full suite (165 files / 953
  tests) green; roadmap `READY`.
- Operational repair on 2026-09-22: the `endpoint-publish`,
  `verify-endpoints` and `publication-evidence` stages were reset in the
  Alpha.16 route state and `publish --yes` resumed, republishing 45 manifests
  (15 retained versions x 3 targets). Blocking verification passed on all 45
  polled URLs.
- Independent remote inspection: every chain `0.2.0-alpha.2` through
  `0.2.0-alpha.16` on `darwin-x86_64` serves `0.2.0-alpha.16` with a 416-byte
  signature. The ladder (`alpha.13 -> alpha.14 -> alpha.15 -> alpha.16`) no
  longer exists.
- Publication evidence regenerated by the route:
  `docs/update/alpha-16-release-publication-2026-09-22.md` (commit `1589185`).

## Navigator Validation

Validated by the Navigator on 2026-09-22 through the real installed-application
route: Alpha.14 was reinstalled from its retained DMG
(`b289b92bcbab3f68e420f3f3cab2d9429cf0787bd061db8453a9eed35c0a23b2`, byte-identical
to the published Alpha.14 artifact) and the running application offered
`0.2.0-alpha.16` directly, with no intermediate Alpha.15 hop.

This closes the gap named as debt when CR074 closed: the deployment route is now
proven by an installed application actually updating from it, not only by
manifest inspection.

## Proportionality and Debt Review

**Proportionate.** The change is one derivation function, its regression tests
and a one-line governance invariant. No product runtime, conversation
authority, Mirror persistence or provider path was touched. The cost of the
repair was bounded by the route's own resumability: only the endpoint stages
were re-run, and the blocking verification grew from 6 to 45 polled URLs
without any manual list.

**Debt accepted, and named.** Two limits ship knowingly:

- The retained set grows linearly with published tags. At 15 versions the
  publication uploads 45 manifests; this is cheap now, but a long-lived channel
  will eventually want a supported-version floor rather than every tag ever
  published.
- Artifact retention is still governed separately from manifest retention. All
  manifests point at the latest artifact, so an older artifact being pruned does
  not break updates, but the two policies remain independent and could drift.

**Debt retired.** Chained updates are structurally impossible: the retained set
is derived from tags rather than hand-listed, the downgrade guard prevents an
older republication from rewriting a newer chain, and the blocking verification
now proves the one-hop invariant across every served version on every target.

## Closure

Closed on 2026-09-22. Implementation and repair merged to `main` through
`2257f7e`; evidence recorded at `eb07520`. Every published chain from
`0.2.0-alpha.2` to `0.2.0-alpha.16` serves `0.2.0-alpha.16`, confirmed both by
the route's 45-URL blocking verification and by independent remote inspection.

## Authority Boundary

Closed under explicit Navigator validation on the installed application. Any
future release remains its own Navigator decision, authorized as the single
release-publication scope defined by CR074.
