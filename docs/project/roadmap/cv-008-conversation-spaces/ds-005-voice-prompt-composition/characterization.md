# TS-1 Characterization — Local Transcription Spike and Contract

**Date:** 2026-09-23
**Machine:** 2019 MacBook Pro, Intel Core i7-9750H (6 cores / 12 threads), macOS 26.6.2, no Metal (CPU + Accelerate).
**Engine:** `whisper.cpp` v1.8.3 (`2eeeba5`), built with `cmake -DBUILD_SHARED_LIBS=OFF -DGGML_METAL=OFF -DCMAKE_BUILD_TYPE=Release --target whisper-cli`. Result: `whisper-cli`, 2.6 MB Mach-O x86_64 linking only `libSystem`, `Accelerate` and `libc++`.
**Samples:** macOS `say` speech (Luciana pt_BR, Samantha en_US) converted with ffmpeg to 16 kHz mono PCM16 WAV. Synthetic voices are harder than natural speech for proper nouns; results are conservative.

## Runtime observations

- `--language auto` roughly doubles wall time on base (18.1 s vs 8.8 s for the PT clip) because detection runs an extra encoder pass. Detection itself was correct (`pt`, p = 0.98).
- `--threads 8` was slower than the default 4 on this CPU (19.4 s vs 8.8 s); hyperthread contention. The boundary keeps the executable default.
- Encode time dominates (5.7 s of 8.8 s). It scales with 30-second windows, so a five-minute clip needs roughly 60–120 s on this machine; the native timeout is 10 minutes and the UI offers Cancel.
- `--no-prints` keeps stdout to the transcript only (one leading blank line and leading space, handled by normalization). Timings go to stderr.
- Apple Silicon builds should enable Metal; this Intel machine is the slow floor.

## Boundary rehearsal through the Rust module

`cargo test real_component_spike -- --ignored` drove the real executable through `run_transcription` with the fixed argument vector:

en.wav  en    audio_seconds=6 duration_ms=6373  transcript="Please summarize the open questions about local transcription and list the next steps for the delivery story."

Temporary WAV files were deleted after each run (asserted).

`cargo test --features development-channel real_install_spike -- --ignored` fetched a loopback manifest generated by `scripts/voice_component_manifest.mjs`, downloaded the executable and model, verified size and SHA-256, installed under a disposable app-data root, reported `ready`, transcribed `en.wav` through the installed component and removed the directory. See the install rehearsal record below.

## Decisions recorded for DS-005

- **Default model:** `base-q5_1`. Smallest acceptable for Portuguese and English dictation. `small-q5_1` may be offered later as an optional heavier model through the same manifest without touching the Composer.
- **Engine:** `whisper.cpp` v1.8.3 `whisper-cli`, statically linked per platform/architecture; macOS aarch64 builds with Metal, x64 without.
- **Language:** `auto` by default for correctness; an explicit hint halves latency and is a candidate Settings refinement, not part of this Delivery Story.
- **Limits:** 5-minute recordings, 9.6 MB WAV bound, 10-minute transcription timeout, transcript bounded by the Composer draft limit.
- **Capture:** WebView `getUserMedia` + `MediaRecorder`, TypeScript WAV conversion (no ffmpeg). WebView permission behavior remains Navigator validation in `Mirror Desktop Dev`.
- **Hosting:** Mirror-controlled `https://updates.mirrormind.sh/mirror-desktop/voice/manifest.json`; artifacts curated with the manifest helper. Publication is a separate release gate.
- **Licenses:** `whisper.cpp` is MIT; Whisper model weights are MIT. Redistribution is compatible.

The rehearsal surfaced two defects that were fixed before this record: `reqwest` compiled with `rustls-no-provider` panics unless a crypto provider is installed process-wide (now installed explicitly with `ring`, matching the updater plugin), and the manifest parser rejected loopback artifact URLs that the downloader admitted on the development channel (loopback admission is now one explicit parser argument, true only for development rehearsals).
